# 速览输出模板与本地记忆 Schema

## 一、对话内 Markdown 速览模板

输出时严格保持高信息密度、零废话；如果某分区为空，直接省略该分区（顶部总览数字照常显示 `0`）。

```markdown
## 分析报告实证速览

> **范围**：周报 `YYYY-Www` + 日报 `YYYY-MM-DD ~ YYYY-MM-DD`（共 N 份，跨期去重后 M 项）  
> **基准**：分支 `<branch>` · 当前工作区（`HEAD <short_hash>`，含 X 个未提交改动文件）  
> **结论**：🔴 仍存在 **A** 项（P0/P1: a1，高价值 P2/优化: a2）｜🟡 本地已修待提交 **B** 项｜🟢 已修复 **C** 项｜⚪ 机制已变失效 **D** 项｜🔵 需实机 **E** 项｜⏭️ 已忽略/暂缓 **F** 项  
> **一句话判断**：<一句直接说清现在有没有上线阻断风险、最值得先做哪 1~2 件事>
```

## 二、写作红线（反废话自检）

1. **禁止照抄原报告段落**：把“代码证据 + 触发条件 + 根因”浓缩成 **1 句大白话**；避免出现“静态分析确认”、“本周期高密度迭代导致”等报告腔。
2. **必须合并同根因项**：同一问题在周报和 3 份日报里出现 4 次，只占 1 个编号，把关联 ID 用 `/` 并列标注。
3. **优化方向必须过“机制变化关”**：若某个性能优化或重构目标对应的代码已经被重构、缓存化或移除，直接判 `🟢 已修复` 或 `⚪ 机制已变·失效`，不放进主区干扰视线。
4. **文件路径一律使用可点击 `file:///` 绝对链接**（Windows 路径转正斜杠），并精准指向当前工作区的实际行号（而非原报告里可能已偏移的旧行号）。
