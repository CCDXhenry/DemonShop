# 分析报告速览与实证核对（review-report-digest）

将冗长的每日/每周分析报告压缩为**一针见血、可直接决策的对话内 Markdown 速览**，并基于当前工作区代码实证确认每条问题与优化方向是否仍然有效。

## 核心原则

- **只读核对**：核对阶段禁止修改业务源码、禁止改动 Git 状态、禁止启动 Roblox Studio Play、禁止在仓库内新增或覆写报告文件。
- **实证优先**：绝不直接复述报告结论，也绝不凭猜测宣称“已修复”；每条问题和优化方向必须对照当前工作区源码给出判断依据。
- **人话直击要害**：不在速览正文贴大段源码或凑字数，每条有效项只说清**本质 / 后果 / 改法与成本**。
- **本地决策记忆**：仅在用户明确指令忽略、暂缓或恢复某条时，读写 `.cache/report-triage.json`（已纳入 `.gitignore`，不入 Git）。

## 执行流程

### 1. 收集报告范围与工作区上下文

运行辅助脚本一次性获取待读报告列表、Git 状态与本地忽略清单：

```bash
python .agents/skills/review-report-digest/scripts/triage_helper.py scan
```

- **默认范围**：最新 1 份 `每周架构分析报告/*.md` + 该周报 `HEAD`/时间窗口之后的全部 `每日代码分析报告/*.md`（自动跳过已被周报 `HEAD` 覆盖的旧日报；若无周报则取最近 7 份日报）。
- **自定义范围**：若用户指定了范围，可加 `--all`（全量）、`--days N`（最近 N 天日报）或直接读取用户指定的报告文件。
- 同时关注脚本输出的 `dirty_files`（未提交改动列表）与 `triage`（`.cache/report-triage.json` 中的已忽略/暂缓记录；已过 `defer_until` 日期的暂缓项自动重新激活）。

### 2. 读取报告并跨期去重

并行读取选定的周报与日报，提取全部候选项并合并去重：

1. **提取范围**：
   - `重点问题`（P0 / P1 / P2 / P3）
   - `架构与性能优化` / `技术债务清单` 中尚未落地的优化方向
   - `测试缺口与待验证事项` 中确有线上/体验风险的项
2. **去重规则**：
   - 按 `模块路径 + 核心函数/机制 + 根本原因` 归一化，将跨日报/周报指向同一根因的条目合并为 1 条，并保留全部关联 ID（如 `ARCH-2026W47-06 / ISSUE-20261124-02`）。
   - 已被后续日报明确记录为“历史误报”的条目直接归入收底区，不重复上主区。

### 3. 对照当前工作区代码实证核对

以**当前工作区最新代码（含未提交改动）**为唯一事实基准，按模块批量并行读取涉及的源码（必要时对照 `功能文档/` 或配置表确认机制是否已调整），将每条归入以下 6 种状态之一：

| 状态标记 | 含义与判定标准 |
|---|---|
| `🔴 仍存在` | 当前工作区源码确认缺陷、风险或优化空间依然成立。 |
| `🟡 本地已修待提交` | 当前工作区代码已修复，但 `git diff` / `git show HEAD:<file>` 显示 `HEAD` 尚未合入（务必提醒别忘提交）。 |
| `🟢 已修复` | 当前 `HEAD` 与工作区均已确认修复，或经完整调用链证实为历史误报。 |
| `⚪ 机制已变·失效` | 相关玩法、功能开关、模块架构或数据流已重构/移除，原问题或优化方向不再适用。 |
| `🔵 需实机确认` | 静态源码无法定论（如帧率体感、多指触控、实机动画穿模等），必须经 Studio Play 或真机实测判断。 |
| `⏭️ 已忽略/暂缓` | 命中 `.cache/report-triage.json` 且仍在有效期内（若相关文件自记录后发生明显改动或已过 `defer_until`，需重新核对并提示）。 |

**验证深度约定**：
- 默认以**快速静态源码核对**为主，不跑耗时全量脚本。
- **仅当**条目明确涉及离线测试门禁或 `--!strict` 类型报错（例如 `test_rules.py` 失败、`ThrowArc` strict 告警）时，按需定向运行对应校验命令（如 `python Tools/Gameplay/test_rules.py` 或 `pwsh -File Tools/check-strict.ps1 <文件>`）以获得确凿结果。

### 4. 按模板输出“一针见血”速览

读取 [references/output-template.md](references/output-template.md)，严格遵循其中的分层结构、三要素表达、编号规则与收底压缩策略，在对话中直接输出 Markdown 速览。

重点检查：
- 顶部必须有 **3 秒总览**（范围、代码基线、各状态数量、一句话风险判断）。
- 主区（`必须优先处理` + `值得处理的问题与优化方向`）统一从 `#1` 连续编号；**每条必须可点击 `file://` 直达源码**，禁止大段贴源码。
- `🟡 本地已修待提交`、`🟢 已修复`、`⚪ 机制已变·失效`、`P3 杂项`、`🔵 需实机确认`、`⏭️ 已忽略/暂缓` 全部压缩在收底区，一眼扫过即可，绝不抢主区视线。
- 末尾必须附带**快捷操作提示**（修复 / 展开细节 / 忽略 / 暂缓 / 恢复）。

### 5. 处理后续交互指令

用户看完速览后回复编号指令时：

- **`修 #1 #3`**：进入正常编码修复流程（遵守 `demonshop-project` 与项目规范，仅修改对应问题并做针对性验证）。
- **`展开 #2`**：展示该条对应的完整代码证据、调用链分析与原报告验收标准。
- **`忽略 #4 原因：...`**：调用脚本写入 `.cache/report-triage.json`：
  ```bash
  python .agents/skills/review-report-digest/scripts/triage_helper.py ignore --key "<fingerprint>" --ids "ID1,ID2" --title "<简短标题>" --reason "<用户原因>"
  ```
- **`暂缓 #5 到 YYYY-MM-DD 原因：...`**：调用脚本写入带截止日期的暂缓记录：
  ```bash
  python .agents/skills/review-report-digest/scripts/triage_helper.py defer --key "<fingerprint>" --ids "ID1,ID2" --title "<简短标题>" --until "YYYY-MM-DD" --reason "<用户原因>"
  ```
- **`恢复 #4`**：调用脚本移除记录：
  ```bash
  python .agents/skills/review-report-digest/scripts/triage_helper.py restore --key "<fingerprint_or_id>"
  ```
- **`key`（问题指纹）格式**：统一使用 `<模块名>::<函数或机制>::<简短根因slug>`（例如 `ProcessingManager::OnRequest::station-distance-check`），不依赖行号，避免代码增删后失配。
