- **问题描述与触发条件**：
  1. 玩家扛着白膜使用手动丢出（`Manager.Throw` -> `Carry.BeginManualToss`），此时白膜状态为 `item.location = "Thrown"`，且带有 `item.poolToss`；
  2. 若玩家朝地图外、悬崖或边缘投掷，或者白膜由于物理下落穿透地面掉入世界虚空（`Position.Y < -40`）；
  3. `ProcessingManager.Update`（L1410-L1421）检测到 `primary.Position.Y < -40`，调用 `Carry.Drop(item, Vector3.new(0, -100, 0), not keep)`；
  4. `Carry.Drop` 将 `item.location` 修改为 `"Ground"`，但**完全没有清除 `item.poolToss`**；
  5. 在其后的每一帧 `Update` 中，由于 `item.poolToss` 依然存在，继续调用 `Carry.AdvanceManualToss`；
  6. 经过落地超时后（`now >= settle`），`AdvanceToss` 触发 `OnSettled` -> `Manager.SettleThrown`，但 `SettleThrown` 检查到 `item.location ~= "Thrown"`（已被改成 Ground），直接 `return` 退出，导致 `FinishGround` 永远无法执行，`item.poolToss` 永远无法被置空；
  7. 结果：`AdvanceToss` 每帧都返回 `true`，`changedMotion` 每一帧都为 `true`，每一帧都调用 `self:Changed()` -> `self.replication:Broadcast(self:Snapshot())`。
- **实际影响**：
  一旦地图中发生一次丢置白膜跌出世界下界，服务端就会陷入每帧向全服所有客户端广播全量 Snapshot 的死循环网络风暴中，造成服务器 CPU 占用暴涨、带宽耗尽和全服玩家延迟飙升，直到服务端崩溃或该白膜被重载。
- **修复建议**：
  1. 在 `Scripts/ServerStorage/Scripts/Carry.luau` 的 `Carry.Drop` 函数起始处或属性赋值处，显式添加清理语句：
     ```lua
     item.poolToss = nil
     item.altarToss = nil
     ```
  2. 在 `Scripts/ServerStorage/Scripts/ProcessingManager.luau` 的 `Manager.SettleThrown` 函数中添加防御性置空：
     ```lua
     function Manager.SettleThrown(self: Manager, item: Types.Item): ()
         if item.location ~= "Thrown" then
             item.poolToss = nil
             return
         end
     ```
- **验收标准**：
  编写针对 `Carry.Drop` 的单元测试：构造 `location = "Thrown"` 且带 `poolToss` 的 item 调用 `Carry.Drop`，断言 `item.poolToss == nil`；构造掉落出界的白膜触发回收后，后续帧中不再持续触发 `AdvanceManualToss`，`self:Changed()` 停止每帧广播。

### ISSUE-20261124-02（历史遗留：2026-11-21 ISSUE-02）

- **问题 ID**：ISSUE-20261124-02

- **代码证据**：
  ```lua
  -- Carry.luau:475-485
  local model = item.model
  local pivot = model:GetPivot() -- 在 PivotTo 之前记录 pivot
  model:PivotTo(toss.rest)
  for _, part in model:GetDescendants() do
      if part:IsA("BasePart") then
          part.CFrame = toss.rest * AltarRestOffset(part, model, pivot)
      end
  end
  ```
- **问题描述与触发条件**：
  白膜祭坛抛掷到达落台终点（`now >= landEnds`）时，若模型中存在任意未标记 `RestPose` 属性的非 `PrimaryPart` 部件（如装饰附件、挂载件或非标准白膜网格）。
- **实际影响**：
  `pivot` 在 `model:PivotTo(toss.rest)` **之前**读取；`PivotTo(toss.rest)` 已将模型部件移至 `toss.rest`。随后 `AltarRestOffset` 的回退分支 `pivot:ToObjectSpace(part.CFrame)` 使用旧 `pivot` 计算已移动部件的局部相对位置，导致模型位移被叠加二次位移，该部件在落台瞬间会发生异常飞离或错位。
- **修复建议**：
  将 `local pivot = model:GetPivot()` 调整至 `model:PivotTo(toss.rest)` 之后读取，或直接将 `toss.rest` 传入 `AltarRestOffset` 作为相对参考系。
- **验收标准**：
  构造包含无 `RestPose` 属性子部件的白膜模型执行 `AdvanceAltarToss` 至落地，落台后子部件相对 `PrimaryPart` 偏移保持一致。
