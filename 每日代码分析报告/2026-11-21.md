### ISSUE-01

- **问题 ID**：ISSUE-01
- **严重程度**：P1
- **置信度**：高（静态分析确认，未进行运行时实测）
- **文件路径及行号**：
  - `Scripts/ReplicatedStorage/Scripts/Client/ClientProcessingManager.luau:1085-1102`、`1341-1344`
  - `Scripts/ReplicatedStorage/Scripts/Client/CurvedPaintView.luau:606-633`、`837-854`
- **代码证据**：
  ```lua
  -- ClientProcessingManager.luau:1341-1344 (每帧 PreSimulation 调用)
  local tossing = self.bodies.IsAltarTossing and self.bodies:IsAltarTossing(item.id, now)
  if (item.flyEnds and now < item.flyEnds) or tossing then
      self.bodies:Fly(item.id, now)
      self.view:ClearSacrifice(item.id)
  ```
  ```lua
  -- ClientProcessingManager.luau:1098-1100 (每帧 RenderStepped 调用)
  if self.view and self.view.SetSacrifice then
      self.view:SetSacrifice(completeFlash.id, brightness, 0)
  end
  ```
  ```lua
  -- CurvedPaintView.luau:849-853
  if self.sacrificeStep[id] == step then
      return
  end
  self.sacrificeStep[id] = step
  UploadTint(texture, shown or 0) -- 同步拷贝 4MB 缓冲 + 遍历 1,048,576 像素 + WritePixelsBuffer
  ```
- **问题描述与触发条件**：
  玩家将曲面（`1024×1024` `EditableImage`）白膜画满 100% 时，客户端收到 `FinishPaint` 设置 `self.completeFlash`（持续 0.32s）并立即请求结束绘画；服务端返回 `EndPaint` 后白膜进入 `Altar` 且 `IsAltarTossing == true`。在此后 0.32s 内的每一帧：
  1. `PreSimulation` 中的 `UpdateAltar` 调用 `ClearSacrifice(item.id)`，将 `sacrificeStep[id]` 归零并同步执行一次全图 `UploadTint(texture, 0)`；
  2. 同帧 `RenderStepped` 中的 `Client.Update` 先调用 `self.view:Update(self.paintId)`，再由 `completeFlash` 调用 `SetSacrifice(id, brightness, 0)`，由于 `sacrificeStep[id]` 刚被归零，必然再次触发全图 `UploadTint(texture, brightness)`。
- **实际影响**：
  `sacrificeStep` 步进缓存彻底失效，起飞抛掷瞬间每帧同步执行两次 `1024×1024` 整图 GPU 纹理上传及一次 104 万次 Luau 像素遍历，导致低端设备/高刷屏幕明显掉帧卡顿，同时引起完成高亮闪烁抖动。
- **修复建议**：
  1. 在 `ClientProcessingManager.UpdateAltar` 中，若 `self.completeFlash and self.completeFlash.id == item.id`，跳过 `self.view:ClearSacrifice(item.id)`。
  2. 在 `Client.Update` 中将 `completeFlash` 的状态推进逻辑置于 `self.view:Update(self.paintId)` 之前或统一交由单一状态控制。
- **验收标准**：
  曲面白膜画满 100% 起飞的 0.32s 内，`CurvedPaintView.SetSacrifice` 不再被 `UpdateAltar` 清零，`UploadTint` 仅在量化 `step` 实际变化时触发，且起飞动画无闪烁抖动与帧尖峰。

### ISSUE-02

- **问题 ID**：ISSUE-02
- **严重程度**：P2
- **置信度**：高（静态分析确认，未进行运行时实测）
- **文件路径及行号**：
  - `Scripts/ServerStorage/Scripts/Carry.luau:360-364`、`423-429`
- **代码证据**：
  ```lua
  -- Carry.luau:360-364
  local function AltarRestOffset(part: BasePart, model: Model, pivot: CFrame): CFrame
      if part == model.PrimaryPart then return CFrame.identity end
      local rest = part:GetAttribute("RestPose")
      return if typeof(rest) == "CFrame" then rest else pivot:ToObjectSpace(part.CFrame)
  end

  -- Carry.luau:423-429
  local pivot = model:GetPivot()
  model:PivotTo(toss.rest)
  for _, part in model:GetDescendants() do
      if part:IsA("BasePart") then
          part.CFrame = toss.rest * AltarRestOffset(part, model, pivot)
      end
  end
  ```
- **问题描述与触发条件**：
  白膜祭坛抛掷到达落台终点（`now >= landEnds`）时，若模型中存在任意未标记 `RestPose` 属性的非 `PrimaryPart` `BasePart`（如附件、饰品、道具挂载件或测试模型部件）。
- **实际影响**：
  `pivot` 在 `model:PivotTo(toss.rest)` **之前**读取；`PivotTo(toss.rest)` 已将部件移至 `toss.rest` 附近，随后 `AltarRestOffset` 的回退分支用旧 `pivot` 计算 `pivot:ToObjectSpace(part.CFrame)`，导致 `(toss.rest - oldPivot)` 的位移被重复叠加到 `toss.rest` 上，该部件直接偏移飞离模型。
- **修复建议**：
  将 `local pivot = model:GetPivot()` 移至 `model:PivotTo(toss.rest)` 之后（或直接将 `toss.rest` 作为 `pivot` 传给 `AltarRestOffset`）。
- **验收标准**：
  构造包含无 `RestPose` 属性子部件的模型执行 `Carry.AdvanceAltarToss` 至 `landEnds`，落台后该子部件相对 `PrimaryPart` 的局部偏移保持不变。

## 4. 架构与性能优化

1. **优化 `CurvedPaintView.UploadTint` 整图全像素遍历（高收益）**
   - **位置**：`Scripts/ReplicatedStorage/Scripts/Client/CurvedPaintView.luau:606-633`
   - **现状**：退出绘画台后白膜保持 `1024×1024` 高分纹理驻留（L158-L161）。每次完成闪烁或献祭高亮（最多 20 步）调用 `UploadTint` 时，都在主线程同步执行 `for pixelIndex = 0, 1048575 do`（104 万次 Luau 循环）并整图提交 4MB 纹理。
   - **建议**：在 `Texture` 结构中维护已着墨像素的稀疏索引表（或 64×64 非空 chunk 集合），`UploadTint` 仅更新有墨迹的像素并按脏块调用 `WritePixelsBuffer`。预计可减少 70%–90% 的主线程 CPU 耗时与 GPU 带宽占用。
2. **`CurvedPaintView.RemoveTexture` 同步清理 `self.sacrificeStep[id]`**
   - **位置**：`Scripts/ReplicatedStorage/Scripts/Client/CurvedPaintView.luau:129-146`
   - **现状**：纹理因超视距或 LRU 淘汰被销毁时未重置 `self.sacrificeStep[id]`，若后续重建纹理且当帧无新提交，可能误判步进已同步而跳过首次 `UploadTint`。建议在 `RemoveTexture` 中补充 `self.sacrificeStep[id] = nil`。
