## 3. 重点问题

### ISSUE-20261126-01

- **问题 ID**：ISSUE-20261126-01
- **严重程度**：P2
- **置信度**：高（静态源码确认，未进行运行时实测）
- **文件路径及行号**：
  - `Scripts/ReplicatedStorage/Scripts/Client/UIManager/init.luau:105-123`
  - `Scripts/ReplicatedStorage/Scripts/Client/ClientProcessingManager.luau:1017`（项目内同坐标系参照注释）
- **代码证据**：
  ```lua
  -- Scripts/ReplicatedStorage/Scripts/Client/UIManager/init.luau:105-119
  local function InsideModalContent(window: Frame, regions: {string}?, gui: ScreenGui, input: InputObject?): boolean
  	if not regions or not input then return false end
  	local point = if input.UserInputType == Enum.UserInputType.MouseButton1
  		then userInputService:GetMouseLocation()
  		else Vector2.new(input.Position.X, input.Position.Y)
  	if not gui.IgnoreGuiInset then point -= guiService:GetGuiInset() end
  	for _, name in regions do
  		local region = window:FindFirstChild(name, true)
  		if region and region:IsA("GuiObject") and region.Visible then
  			local topLeft = region.AbsolutePosition
  			local bottomRight = topLeft + region.AbsoluteSize
  			if point.X >= topLeft.X and point.X < bottomRight.X and point.Y >= topLeft.Y and point.Y < bottomRight.Y then
  				return true
  			end
  		end
  	end
  	return false
  end
  ```
- **问题描述与触发条件**：
  在 Roblox 引擎中，`UserInputService:GetMouseLocation()` 返回**包含顶栏（GuiInset）**的屏幕坐标，而 `InputObject.Position` 返回**已扣除顶栏高度**的视口坐标（本项目 `ClientProcessingManager.luau:1017` 已明确注释：`输入事件里的坐标比 GetMouseLocation 少一个顶栏高度`），且 `GuiObject.AbsolutePosition` 始终位于已扣除顶栏偏移的坐标系中。
  `InsideModalContent` 在 `gui.IgnoreGuiInset == true`（本项目 `GameScreenGui` 默认开启）时，对 `MouseButton1` 直接使用 `GetMouseLocation()` 未减去 `guiService:GetGuiInset()`，导致鼠标判定点 Y 轴相对 `AbsolutePosition` 向下偏移约 58px；而在 `gui.IgnoreGuiInset == false` 时，对 `Touch` 输入反而重复减了一次 `GuiInset`。
- **实际影响**：
  PC 端玩家打开随身商店（`PersonalShop`）等模态窗口后，点击面板底部约 58px 内的空白区域或边缘时，`point.Y >= bottomRight.Y` 会误判为点击弹窗外部，导致商店窗口意外关闭；反之点击标题栏上方约 58px 空白遮罩时无法正常关闭弹窗。
- **修复建议**：
  仅对 `GetMouseLocation()` 减去 `guiService:GetGuiInset()`，将其与 `input.Position` 及 `AbsolutePosition` 统一到同一坐标系，移除错误的 `if not gui.IgnoreGuiInset` 分支：
  ```lua
  local point = if input.UserInputType == Enum.UserInputType.MouseButton1
  	then userInputService:GetMouseLocation() - guiService:GetGuiInset()
  	else Vector2.new(input.Position.X, input.Position.Y)
  ```
- **验收标准**：
  1. 更新 `Tools/Gameplay/test_foundation_ui.luau` 中 `modalContentRegions` 用例，分别验证 `IgnoreGuiInset = true/false` 下鼠标（含顶栏偏移的 `GetMouseLocation`）与触控（无顶栏偏移的 `input.Position`）点击面板上下边缘的准确命中与关闭行为；
  2. Studio 实机在 `PersonalShop` 面板底部边缘与标题上方空白遮罩分别用鼠标点击验证无偏移误关。

  ```lua

  	FillPaintBatch(self, session, item, if record then PersonalRules.GetRuneBatch(record.levels.runeBatch) else 1)
  	self:Restack(player)
  ```
- **问题描述与触发条件**：
  `Manager.BeginPaint` 先调用 `FillPaintBatch`，随后才调用 `self:Restack(player)`，且 `FillPaintBatch` 仅遍历玩家当前可见肩扛数组 `self:Carried(session.player)`（上限 `CarryVisibleLimit = 8`），未检查 `record.carryOverflowCount` 中存储的未画白膜。
  当玩家装备高阶搬运工具（容量 15/30）并混合携带多具已画白膜（例如 6 具已画 + 2 具未画在可见队列）以及若干溢出未画白膜（`carryOverflowCount > 0`），且存放池为空时，触发连画（上限 3–5 具）会少放白膜，而紧随其后的 `self:Restack(player)` 又会把溢出白膜具现化回玩家肩上。
- **实际影响**：
  高阶搬运 + 连画混合场景下，玩家明明携带有足够未画白膜却无法填满连画槽位，或在存放池有存货时错误消耗公共存放池的白膜而非玩家自身携带的溢出白膜。
- **修复建议**：
  在 `FillPaintBatch` 遍历完 `stack` 且 `#batch < limit - 1` 时，若 `record and record.carryOverflowCount > 0`，先从 `record.carryOverflowCount` 通过 `CreateStationBody` 生成未画白膜填入 `batch` 并递减计数，最后再回退调用 `TakePoolBody(self, true)`。
- **验收标准**：
  在 `Tools/Gameplay/test_personal_upgrades.luau` 或 `test_station_and_potions.luau` 中补充用例：玩家携带 6 具已画 + 2 具未画可见白膜、4 具 `carryOverflowCount` 且存放池为空，以 5 连画进入画符台，断言 `batch` 填满 4 具（共 5 具）且 `carryOverflowCount` 相应扣减。

  ```lua
  -- Scripts/ServerStorage/Scripts/ProcessingManager.luau:2295-2308
  	local record = self.players[player]
  	if record then
  		for index = 1, record.carryOverflowCount do
  			local offset = Vector3.new((index - 1) % 5 - 2, 0, math.floor((index - 1) / 5) + 1)
  			local position = origin + offset * Physics.CarryReleaseSpacing
  			local body = CreateStationBody(self, "Ground", "Unpainted", CFrame.new(position))
  			if body then
  				Carry.Drop(body, position, false)

  			end
  		end
  		record.carryOverflowCount = 0
  	end
  ```
- **问题描述与触发条件**：
  玩家装备顶配搬运工具 `GRAVITY PACK`（容量 30，`CarryVisibleLimit = 8`）时，`carryOverflowCount` 最高可达 22。当玩家死亡或离场触发 `ReleasePlayer` 时，服务端在单帧内无条件循环克隆最多 22 具完整 R15 `WhiteR15` 模型并执行 `Carry.Drop`，既未校验 `Config.MaximumBodies`（60）的同服身体总量保护上限，也未对水平网格偏移后的落点做墙体遮挡检查。
- **实际影响**：
  多人同时死亡/断线或单人高频拾取并重置角色时，可突破 `Config.MaximumBodies = 60` 的实体总量上限并引发单帧大量 R15 骨骼/物理装配尖峰；贴墙死亡时网格偏移可能将部分白膜生成至墙体内部或地图边界外（需等待掉出 `-40` 后回收）。
- **修复建议**：
  在循环前统计当前 `self.items` 中的 `Body` 数量，每次具现化前检查 `bodyCount < Config.MaximumBodies`（并可限制单次地面掉落溢出数量上限），超出部分直接归入 `self.poolOverflowCount += 1`（复用已有兜底分支）。
- **验收标准**：
  在离线回归测试中构造场景已有 55 具 `Body` 且玩家 `carryOverflowCount = 20`，调用 `ReleasePlayer` 后断言场景 `Body` 总数不超过 `Config.MaximumBodies`（60），且剩余 15 具准确转入 `poolOverflowCount`。
