## 3. 重点问题

### ISSUE-20261125-01

- **问题 ID**：ISSUE-20261125-01
- **严重程度**：P1
- **置信度**：高（静态源码确认，未进行运行时实测）
- **文件路径及行号**：
  - `Scripts/ServerStorage/Scripts/ServerGameManager/ServerPlayerChatCommandManager.luau:17-22, 70-89`
  - `Scripts/ReplicatedStorage/Scripts/Shared/GameConfig.luau:18`
- **代码证据**：
  ```lua
  -- Scripts/ReplicatedStorage/Scripts/Shared/GameConfig.luau:18
  GameConfig.GameId = 0000 -- 本项目正式体验 ID
  ```
  ```lua
  -- Scripts/ServerStorage/Scripts/ServerGameManager/ServerPlayerChatCommandManager.luau:17-22, 70-86
  local function IsProductionEnvironment(): boolean
  	if RunService:IsStudio() then
  		return false
  	end
  	return Config.GameId > 0 and game.GameId == Config.GameId
  end
  ...
  	if not IsProductionEnvironment() then
  		local addCommand = folder and folder:FindFirstChild("AddCoinsCommand")
  		if addCommand and addCommand:IsA("TextChatCommand") then
  			scope:Connect(addCommand.Triggered:Connect(function(source: TextSource, unfilteredText: string): ()
  				if IsProductionEnvironment() or not GMConfig.IsGMPlayer(source.UserId) then
  					return
  				end
  				...
  				Info.AddCoins(player, amount)
  			end))
  ```
- **问题描述与触发条件**：
  `AddCoinsCommand` 旨在仅于非正式环境辅助测试加金币，但 `IsProductionEnvironment()` 在非 Studio 环境下使用 `Config.GameId > 0 and game.GameId == Config.GameId` 判断是否为生产环境。由于当前仓库中 `GameConfig.GameId` 默认为 `0000`（`0`），或未来发布至新 Universe 时若漏改 `GameConfig.GameId`，任何线上非 Studio 服务器都会使 `IsProductionEnvironment()` 返回 `false`（fail-open），导致 `AddCoinsCommand` 在生产环境被注册并启用。
- **实际影响**：
  尽管命令受 `GMConfig.IsGMPlayer(source.UserId)` 限制，不会直接暴露给普通玩家，但违背了“生产环境彻底禁用加金币命令”的安全隔离边界；一旦上线忘记填写 `GameConfig.GameId`，所有 GM 账号均可在正式服单次刷取最高 `Config.MaximumCoins` 金币，破坏线上经济与风控审计。
- **修复建议**：
  将 `IsProductionEnvironment()` 改为 **fail-closed** 策略：非 Studio 环境默认一律视为生产环境，仅在 `RunService:IsStudio()` 为真，或显式命中受控的测试 `TestGameIds` / `TestPlaceIds` 白名单时返回 `false`。若仍沿用 `Config.GameId` 判定，至少应在 `Config.GameId <= 0` 时直接返回 `true`：
  ```lua
  local function IsProductionEnvironment(): boolean
  	if RunService:IsStudio() then
  		return false
  	end
  	if Config.GameId <= 0 then
  		return true
  	end
  	return game.GameId == Config.GameId
  end
  ```
- **验收标准**：
  在 `Tools/Gameplay/test_foundation_chat.luau` 中新增用例：模拟 `RunService:IsStudio() == false` 且 `Config.GameId == 0`（以及 `game.GameId ~= Config.GameId`），断言 `AddCoinsCommand` 不被注册且触发无效。

## 4. 架构与性能优化

1. **客户端 `UpdateAutomationViews` 事件驱动拆分（对应 ISSUE-20261125-02）**：
   - 将 6 个解锁底盘与井盖的全量子树更新从 10 Hz `Client.Update` 轮询中剥离，仅在 `Coins` 或 `unlockedFacilities` 变化时按脏状态增量更新，可消除客户端 95% 以上无意义的 `GetDescendants()` 调用与 UI 属性重写。
2. **服务端 `AutomationAgents` 静止态零 `PivotTo` 与 `RaycastParams` 帧内复用（对应 ISSUE-20261125-03）**：
   - 避免 60 Hz 服务端心跳对静止 R15 Rig 重复写入 `PivotTo`，并将 `SampleFloorY` 的射线参数按帧复用，降低服务端 CPU 与物理/复制开销。
3. **本次变更中的正向架构亮点（予以肯定）**：
   - **自动化状态机与实体/虚拟溢出解耦**：存放池、药水架与自动线三处断点统一采用“场景可见实体上限 + 虚拟溢出计数”模型，防止长时间挂机导致场景实例数无限膨胀引发服务端/客户端崩溃；
   - **`AutoRunePattern` 按朝向缓存**：自动符文落印模板按 `PartName|Size|LocalUp` 量化缓存，避免每 2 秒重复遍历曲面网格三角形；
   - **`Ragdoll.SetMode` 物理所有权移交顺序修复**：先全部解锚并切换关节，再按 `AssemblyRootPart` 去重执行 `CanSetNetworkOwnership` + `SetNetworkOwner`，彻底规避了半解锚状态下移交网络所有权失败的顽疾。
