# 白膜客户端主导物理与表现重构方案

2026-11-18 · DemonShop · 设计待实施。适用对象为加工链中的 Body。玩家角色、手持武器和药水分别沿用现有责任人。

**先让一个客户端展示实体接管白膜姿态，再迁移权威物理。** 当前白膜确实会弯曲和倒地。需要改变的是接触从哪里传入身体、动量怎样传到末端，以及倒地姿态怎样连续过渡到肩上。第一项对照实验应固定模型、玩家动画、镜头、音量和命中特效，只切换白膜姿态驱动。主片约 18–29 秒可直接作为 A 组。[连续三击与肩扛原片](../.cache/obs-viewport/white-baseline/03-three-hits-carry.mp4) · [采样方法与原始数值](白膜客户端主导物理与表现实施记录.md)

**实测边界。** 目标 Place 的初始六具 NPC 均为 15 个 Motor6D，未发现 AnimationConstraint。步行状态只有头、上躯干、下躯干可碰撞。主样本两次普通受击沿同一方向分别平移约 0.93、1.13 studs；关闭速度约束时两次都接近 4 studs/s。连续第三击后，现场读到 14 个球窝启用、1 个根 Motor 保持启用和 15 个碰撞部件；肩扛后仍有 14 个球窝，但 16 个部件全部 Massless、0 个可碰撞，物理所有者变为持有者。录像能看到肢体下垂，也能看到从地面到肩部的构型变化很快；当前样本无法量化远端抖动。[基线记录与帧索引](白膜客户端主导物理与表现实施记录.md)

## 2. 权威实体与展示实体

| 场合 | 服务端持有 | 每个客户端持有 |
|---|---|---|
| 街道行走、普通受击 | Item、稳定 ItemId、合法根位、Humanoid 导航与速度、等效躯干阻挡边界、hits/version、前摇与停步窗。第一阶段继续使用现有模型 | 一具按原白膜克隆的可见 R15，根跟随已复制权威根；本地 Animator 提供底姿。接触与普通受击只加姿态偏移 |
| 击晕、地面 | 第三次合法命中才设置可拾取状态。最终方案用服务端根与简化地面形体决定滑移、静止位、遮挡、可达范围及越界恢复，动态权威装配显式归服务器 | 从最后一个可见动作接入局部真物理，仿真到睡眠或超时，缓存落地姿态。远处直接使用相同朝向的地面姿势 |
| 肩扛、放下 | version 与 holder 在同一事务提交；服务端按持有者合法躯干和肩偏移算物品根。搬运时用服务端跟随的非碰撞权威锚，保持与玩家装配独立。释放用服务端持有者位置、合法速度、地面查询和现有 SafePose | 收到归属后从当前姿态抬起；本地和旁观者分别采样自己看到的玩家肩部、速度、转身。肩部锚稳定，前臂与小腿保留惯性 |
| 池、工位、祭坛、转化 | 静态摆位、会话、工位版本、覆盖、转换和奖励。保留含原网格与关节附件的服务端画符校验实体 | 同一 id 在 Static/Table 间转模式。操作者查询当前可见白膜；旁观者使用已校验画符姿态。变为药水时结束白膜生命周期 |

实施顺序允许暂时保留复制的原 R15。最终权威代理需按实测的头/躯干轮廓、脚底高度、碰撞组、根偏移制作并做 A/B；不能把过大的统一盒子作为可拾取或命中范围。动态根归服务端，静态锚使用 Anchored。服务端仅在有校验需求的工作台维持完整几何。展示实体的形体、物理速度及肩部误差均不写回业务位置。[Roblox 网络所有权](https://create.roblox.com/docs/physics/network-ownership)

**保留的业务契约。** 三次累计命中、无自动苏醒；攻击距离 7 studs、冷却 0.6 s、前摇 0.16 s、同目标选择窗 1.4 s、停步 0.75 s；交互 8 studs，现场 E 长按 0.5 s。普通击退改用服务端一次有界位移响应或瞬时冲量加阻尼，用场景扫掠、墙面截断及上述实测位移验收，保留近战可追击性。街道人口 6、身体上限 32、池/架容量各 8、覆盖目标 70%、祭坛 10 s、提交 100 金币，沿用各自配置。客户端预测从不会创建合法第三击、持有者或加工资格。

## 3. 模块职责与一帧的写入顺序

| 模块 | 输入、输出与所有权 |
|---|---|
| WhiteBodyPresentationManager | 由 ClientProcessingManager.Init 注入 State/Delta、攻击通知、画符与生命周期；按 id 注册单一可见模型、动画轨、局部物理、LOD 和清理句柄。每帧统一调度。提供 GetVisualPart、GetPaintModel，交互继续取 GetAuthorityModel |
| JointAdapter | Bind 时按两端部件与附件识别 Root/Waist/Neck 及成对肢链，保存初始属性、关节轴、静止坐标和限位。Motor6D 用 Part0/1、C0/C1；AnimationConstraint 用 Attachment0/1、Transform、IsKinematic 和驱动力。复用匹配附件的球窝；同一关节只选一个驱动。同名歧义、断链或缺根记录一次并降级到原展示 |
| Spring | 保存局部位移/角位移及速度，用按 dt 的阻尼振子积分。参数为频率 Hz、阻尼比、偏移与速度上限。叠加冲量时保留前次速度；长帧夹步长、限制子步，超限回到当前目标。30/60/120 FPS 回弹时长应一致 |
| PoseMixer | 合成 Animator 底姿、接触偏移、受击和肩扛残余；以关节局部轴组合并限位。唯一有权通过适配器提交程序姿态。物理接管掩码排除对应关节；过渡以缓存起始姿态和权重完成 |
| SoftContact | 近身时对躯干、肩/髋做短扫掠或距离查询；过滤自己、武器装饰和代理副本，运动相对速度在接触法线上投影，经力臂分配给腰、同侧肩/髋。设置进入/退出滞回、作用上限和离开衰减。持续贴靠趋于小偏移，人物仍受原阻挡 |
| ImpactReaction | 消费本地预测或远端 Hit 的时间、方向、接触点、次数；把接触点转到躯干局部，按力臂注入腰肩与颈部，延迟传到肘腕。第一击短收，第二击承接残余速度扩大失衡，第三击先预测失衡，再由权威 Down 允许落地 |
| LocalRagdoll | 近景只开放选定链的本地球窝与简化接触形体，Root/支撑躯干有界跟随权威地面位；局部物理只与地面/静态场景碰撞，隔离所有玩家、业务目标与其他展示体，相邻肢体成对隔离。保留入场速度，限幅、休眠、回收。无可用额度时直接用程序化落地 |
| CarryMotion | 从可见上躯干到缩放后的玩家肩点做平滑抬升；过滤支撑点的线加速度与角速度，用相反方向的腰、肘、膝弹簧表现启步滞后、转弯外摆、停步回落。丢弃从本帧姿态续接；权威释放速度仍由服务端给出 |

**时序。** PreAnimation 撤销且只撤销本管理器上次写入的偏移，恢复可供 Animator 取样的底姿。PreSimulation 缓存本帧 Animator 结果，读取状态、更新弹簧、分配关节驱动掩码，按父子顺序提交一次。物理步结束缓存求解后的世界姿态供下一次交接；渲染阶段只读姿态更新纹理、提示与相机。退出物理前先捕获实际相对变换，在同一物理步禁用相应球窝、恢复运动学驱动并从捕获姿势混出。工作台操作者的物理链、旁观者的姿态插值与街道 PoseMixer 彼此互斥。玩家的 CharacterPresentation 只写玩家轨道。[Motor6D](https://create.roblox.com/docs/reference/engine/classes/Motor6D) · [AnimationConstraint](https://create.roblox.com/docs/reference/engine/classes/AnimationConstraint)

## 4. 数据与网络协议

| 数据 | 字段及语义 |
|---|---|
| 权威 ItemView（沿用） | id、kind、stage、location、holder、version、model、hits、progress、visualCount。Street 且 hits ≥ StunHits 表示街头击晕；Ground 与 Carried 由 location 表示。根位优先读复制代理，holder 使用 UserId |
| 本地 BodyView（新） | id、authorityModel、visualModel、bindGeneration、appliedVersion、mode、jointMap、rootTarget、springState、physicsMask、sleepPose、predictionTokens、LOD、cleanup。generation 在模型替换、流失/重绑时递增；旧异步结果先验代次再落地 |
| 配置（新） | PhysicsConfig.Presentation 作为默认值的唯一入口，分 Contact、Hit、Fall、Carry、LOD、Limits。关节限位引用已有 Joints；服务端平衡读取 GameConfig。客户端只读已验证且有 revision 的有效快照 |
| 输入与命中（沿用） | GameRequest.Attack 带 target、观察到的 version、attackSequence。服务端按现有校验广播 Hit，包含 actor、id、version、hits、started、direction、position，以 AttackResult(sequence, hit) 回复发起人；第三击资格最终来自 ItemView |
| 状态与补发（沿用为主） | GameNotify.State 为完整 revision，Delta 为 revision、变更项和 removed。新客户端缓存每个 id 的最近版本，并对缺基线/跳号触发现有 Sync 重取全量。状态优先于瞬态反馈。生成或模式变更若需确定落地方向，**可选**在变更项中增加服务端 modeStarted、落地方向与有限初速度，并版本化；迟加入直接从当前状态建姿 |
| 画符（保留） | Paint、PaintVisual、PaintPose、VisualDelta、VisualSnapshot、SyncComplete 保留原有 session、sequence、bodyPose、面/三角与重心坐标等字段。工作台为权威可见面重建按批携带必要姿态；街道、肩扛、地面不发送肢体姿态流 |

输入时立即播挥击，按本地 0.16 s 前摇在目标仍合理时注入反应，网络往返不在播放条件中。以 (actor, attackSequence) 关联预测，以 (id, version) 去重确认。成功时升级现有反应，Hit/AttackResult/Delta 先后互换也只播一次。拒绝、目标变更、超时或重生时按令牌衰减旧偏移；误判第三击只回收可见失衡，不能显示拾取提示。已过表现窗口的 Hit 只推进版本。缺模型的状态先缓存，实例到达后按最新状态绑定。连续远端攻击从事件发生时间快进有界窗口，多次合成限速。

**热调方案。** 在 Studio 客户端以有类型的 ApplyOverrides(patch, revision) 更新配置，字段有单位、范围和有限数校验，整份验证后在下一次 PreSimulation 原子切换。弹簧保留速度并按新限幅夹紧；改物理解算模式等到本轮物理退出。调前、调后记录 revision、有效参数和同场景原片，Reset 恢复默认。不设玩家可写的网络调参入口。建议初值：接触腰偏角上限 10°、腰/四肢 4–7 Hz、阻尼比 0.75–1.0、末端延迟 25–70 ms、抬肩 0.22–0.35 s、近景真物理最长 0.65 s。这些数值用于首轮对照，需同资产录像定稿。

## 5. 生命周期与颜料交接

1. **生成与可见性交接。** 白膜以 ItemId 关联，clone 复用 WhiteR15 的 MeshId、尺寸、面名、SurfaceVersion、UV 与绘画标记。清除脚本、业务提示、旧执行器与旧搬运附件，保留或按适配器重建所需 rig/Animator。先完成绑定和首帧姿态，再隐藏源并显示副本。保存源部件原 LocalTransparencyModifier；初始化失败立即用原体。权威实体保留业务查询，普通展示件不参与通用射线。
2. **行走到倒地。** 移动底姿由权威根速度和 MotionState 选择。普通击退只让根跟随合法位移，预测偏移在小范围内收敛；超大误差或越界传送重置弹簧。末击从当前走姿/受击姿势捕获位置和速度，再接局部物理。地面休眠后保留最终姿态和最近支撑面。
3. **拾取、转交与放下。** E 对准原生提示，服务端复核目标版本、空手、合法位置、距离与视线，先提交归属再启动抬升。两人抢同一件只接受一次。玩家离场、死亡或肩点消失，服务端沿用 ReleasePlayer/Drop 处理并广播；客户端立即释放旧肩引用，等待最新合法根，距离超限或重生不得牵拉玩家。
4. **工作台与静态工位。** 每个 id 只向 PaintView.Bind 提供当前显示模型。进入 Table 时关闭街道弹簧与挂肩驱动，原样保留 PaintBodyPose 的上躯干局部坐标、14 个有效关节验证和只在白膜上的采样射线。操作者当帧可画，观察者插值。把画笔命中部件名、面/三角、重心坐标交给既有 Painting.Apply，仍由服务端重建姿态、射线、Stamp 和面积。离台只重绑显示模型，不调用会清 segments 的 Remove。活跃 1024、观察 512、最多 8 张驻留、4 ms 栅格预算保持现有含义。[PaintView](../Scripts/ReplicatedStorage/Scripts/Client/PaintView.luau) · [CurvedPaintView](../Scripts/ReplicatedStorage/Scripts/Client/CurvedPaintView.luau) · [Painting](../Scripts/ServerStorage/Scripts/Painting.luau) · [PaintBodyPose](../Scripts/ReplicatedStorage/Scripts/Shared/PaintBodyPose.luau)
5. **回收与重入。** 流出或 LOD 淘汰只释放本地姿态、轨道、约束、连接和模型引用，颜料记录仍按 id 保留。流入、晚加入或丢 Delta 时从最新 State/VisualSnapshot 恢复。removed、转化成药水或管理器 Destroy 才终结该身体的渲染资源，解除所有绑定并恢复该管理器隐藏的源；用户已有视觉设置按绑定前值恢复。

## 6. 实施阶段与验收

## 7. 性能预算、风险与回滚

以下均为新增白膜表现的工程预算，尚无实测性能结论。在基线和新实现各采 60 s 稳态及 10 s 突发，预热后取 P50/P95、峰值，记录设备、画质、帧率和可见数量。分别测桌面 60 FPS 与移动端 30 FPS；场景取街道 6 具及总量 32 具，另测绘画同时观察。使用 MicroProfiler 标签区分接触、混合、求解与原有栅格化。

| 资源 | 首轮预算与超额策略 |
|---|---|
| 客户端脚本 | 6 具近景合计 P95 ≤1.0 ms/帧（桌面）、≤1.5 ms/帧（移动）；静止/远景按需更新，优先保留操作者目标、肩扛体与工作台 |
| 查询、真物理 | 桌面最多 2 具、移动最多 1 具同时短时真物理，每具最多 6 条活动关节；近景每体最多 3 个短查询/步，每客户端总量上限 12，超限轮换。工作台操作者优先占用求解资源并沿用其验证骨架 |
| LOD、内存 | 近景建议 24 studs 内逐步，中景到 60 studs 降到 15 Hz 后插值，远景用简姿/休眠，加 4 studs 滞回。单客户端完整动态副本初定最多 6 具，远处可回显静态源或轻姿态；纹理不因模式切换重建。50 次进出后克隆、连接和 EditableImage 计数回稳 |
| 网络、服务端 | 街道/搬运新增逐帧肢体包目标 0；每击最多沿用一次 Hit 和一次发起者 Result，加既有业务 Delta。相同行为下记录 Remote 与物理复制 KB/s，服务端物理步 P95 不高于原版；同时核对峰值、代理数与画符例外 |

**回滚顺序。** 用服务器选择的会话级表现版本让代理和客户端驱动成对上线。先在保留原 R15 的模式下按模块开关验证，旧客户端始终有完整源可看。切到轻代理前需完成能力协商或按新服务器实例分组；混合版本统一留在旧实体模式。单项失败时先停 LocalRagdoll/SoftContact，再退回仅动画，释放驱动与纹理绑定。全量回退时先以当前权威 id/version、holder、工位及画符历史重建完整原体并发 State，客户端确认替代实体已绑定后恢复可见性，再回收展示体/代理；仅可安全停服切版时，在新会话恢复旧配置。回滚不重发奖励或重置业务进度。

重点风险为双写、客户端与远端根偏差、AJU 根连接丢失、颜料绑错模型、地面穿透、贴肩时反推玩家和 LOD 突变。分别以写入计数、根误差、双 rig 覆盖、历史键与纹理核对、静态场景碰撞白名单、服务器所有权检查和滞回测试验收。任一权威计数/归属分叉、颜料历史丢失或重复奖励均停止扩大灰度；性能超预算先降视觉更新与物理名额。
