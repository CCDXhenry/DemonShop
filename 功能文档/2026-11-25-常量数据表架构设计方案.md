# DemonShop 常量数据表架构设计方案

> 日期：2026-11-25  
> 状态：已实施（待 Studio 内试用插件联调）  
> 目标：将当前硬编码在 `GameConfig.luau` 与 `GameTexts.luau` 中的武器、背包、个人能力升级及自动化设施常量，迁移至团队标准的 **Excel → excel2json → JSON → GameDatasExtension / LocalizationExtension → GameData 只读查询层** 架构。

## 2. 总体架构与工具链约定

本方案严格对齐仓库配表规范与团队现有 Studio 插件（`GameDatasExtension.lua`、`LocalizationExtension.lua`）：

```text
ExcelData/<中文业务名>.xlsx
        │  运行 ExcelData/Excel表格转json文件.bat (GBK/CP936 无 BOM)
        │  调用 Tools/excel2json/excel2json.exe --header 3 --cell_json --exclude_prefix @ --array
        ▼
JsonData/<EnglishName>Data.json
        │  Studio 插件「读取Json数据」(GameDatasExtension.lua)
        │  将 JSON 解析为原生 Lua table，写入 GameConfig 子 ModuleScript
        ▼
ReplicatedStorage.Scripts.Shared.GameConfig.<EnglishName>Data
   ├─ 运行时：由 Shared/GameData.luau 统一 require、校验、建索引并 freeze
   └─ 本地化：由 Studio 插件「抓取新翻译文本」(LocalizationExtension.lua)
              自动递归扫描 GameConfig 子模块中以 `_t` 结尾的字段写入 CSV
```

### 2.1 三行表头与导出约定

根据 `Tools/excel2json/Code/JsonExporter.cs`（`--header 3`）：

- **第 1 行**：英文字段名（列名）；以 `@` 开头的列导出时自动排除（用于策划中文备注）。
- **第 2 行**：字段类型（`int`、`float`、`string`、`bool`）；空单元格会按该类型自动填充默认值（`0`、`0`、`""`、`false`）。
- **第 3 行**：中文字段说明。
- **第 4 行起**：正式配置数据。

### 2.2 表与文件映射清单（共 4 张表）

价格列全部并入各自实体表，消除原先独立的 `PersonalUpgradeCosts`。

| 序号 | Excel 源文件 | 导出 JSON 文件 | Studio / Script Sync 子模块路径 |
| --- | --- | --- | --- |
| 1 | `ExcelData/武器表.xlsx` | `JsonData/WeaponData.json` | `Scripts/ReplicatedStorage/Scripts/Shared/GameConfig/WeaponData.luau` |
| 2 | `ExcelData/背包表.xlsx` | `JsonData/CarryToolData.json` | `Scripts/ReplicatedStorage/Scripts/Shared/GameConfig/CarryToolData.luau` |
| 3 | `ExcelData/个人能力升级表.xlsx` | `JsonData/PersonalAbilityData.json` | `Scripts/ReplicatedStorage/Scripts/Shared/GameConfig/PersonalAbilityData.luau` |
| 4 | `ExcelData/自动化设施表.xlsx` | `JsonData/AutomationFacilityData.json` | `Scripts/ReplicatedStorage/Scripts/Shared/GameConfig/AutomationFacilityData.luau` |

### 2.3 BAT 转换命令设计

`ExcelData/Excel表格转json文件.bat`（**GBK/CP936 编码、无 UTF-8 BOM**）：

```bat
cd /D ../Tools/excel2json
excel2json --excel ../../ExcelData/武器表.xlsx --json ../../JsonData/WeaponData.json --header 3 --cell_json --exclude_prefix @ --array
excel2json --excel ../../ExcelData/背包表.xlsx --json ../../JsonData/CarryToolData.json --header 3 --cell_json --exclude_prefix @ --array
excel2json --excel ../../ExcelData/个人能力升级表.xlsx --json ../../JsonData/PersonalAbilityData.json --header 3 --cell_json --exclude_prefix @ --array
excel2json --excel ../../ExcelData/自动化设施表.xlsx --json ../../JsonData/AutomationFacilityData.json --header 3 --cell_json --exclude_prefix @ --array
pause
```

## 4. 运行时代码架构设计

### 4.1 `GameConfig` 目录结构化与瘦身

由于 `GameDatasExtension.lua` 与 `LocalizationExtension.lua` 均固定查找 `ReplicatedStorage.Scripts.Shared.GameConfig` 下的子 `ModuleScript`，本地文件目录按 Script Sync 约定调整为（与 `Client/UIManager/init.luau` 保持一致）：

```text
Scripts/ReplicatedStorage/Scripts/Shared/
├── GameConfig/
│   ├── init.luau                   -- 原 GameConfig.luau，移除 9 处旧集合常量
│   ├── WeaponData.luau             -- 由插件导入（格式与 GameDatasExtension 输出一致）
│   ├── CarryToolData.luau          -- 由插件导入
│   ├── PersonalAbilityData.luau    -- 由插件导入
│   └── AutomationFacilityData.luau -- 由插件导入
└── GameData.luau                   -- 新增：只读强类型数据表查询模块
```

**`GameConfig/init.luau` 变更边界：**
- **彻底删除**：`AutomationFacilityOrder`、`AutomationFacilities`、`AutomationFacilityConfig`（迁至 `GameData`）、`PersonalUpgradeOrder`、`PersonalUpgradeCosts`、`PersonalMoveTiers`、`PersonalRuneBatches`、`PersonalSellBonuses`、`PersonalWeaponTiers`、`PersonalCarryTiers`。
- **保留不动**：参考基础框架全部头部字段/类型/工厂函数（`GameVersion`、`PlayerSaveInfo`、`CreateDefaultPlayerSaveInfo` 等），以及全局标量参数。
- **保留为全局回退值**：`GameConfig.AttackCooldown`（`0.6`）、`GameConfig.WeaponSlashAnimation`（地狱打手 AI 及表内留空回退）、`GameConfig.WeaponSlashSound`（表内留空回退），并在注释中注明“单武器配置以武器表为准，此处仅作空值回退与 AI 共用默认值”。

### 4.2 新增独立数据查询模块 `Shared/GameData.luau`

职责：唯一直接 `require` `GameConfig` 下 4 张子数据表的模块；模块加载时完成排序、合法性断言、索引构建和 `table.freeze` 只读保护，对外暴露严格 `--!strict` 类型和零副作用查询函数。

**导出类型：**

```luau
export type UpgradeCategory = "moveSpeed" | "runeBatch" | "sellBonus" | "weapon" | "carryTool"

export type WeaponConfig = {
	level: number,
	id: string,
	name_t: string,
	model: string,
	cost: number,
	damage: number,
	targets: number,
	shape: string,
	range: number,
	angle: number,
	width: number,
	attackCooldown: number, -- 若表内 <= 0 则在初始化阶段解析为 GameConfig.AttackCooldown
	slashAnim: string,      -- 若表内 == "" 则在初始化阶段解析为 GameConfig.WeaponSlashAnimation
	slashSound: string,     -- 若表内 == "" 则在初始化阶段解析为 GameConfig.WeaponSlashSound
}

export type CarryToolConfig = {
	level: number,
	id: string,
	name_t: string,
	model: string,
	cost: number,
	capacity: number,
}

export type MoveTierConfig = {
	level: number,
	cost: number,
	walk: number,
	sprint: number,
	unlimited: boolean,
}

export type RuneBatchConfig = {
	level: number,
	cost: number,
	runeBatch: number,
}

export type SellBonusConfig = {
	level: number,
	cost: number,
	sellBonus: number,
}

export type AutomationFacilityConfig = {
	order: number,
	id: string,
	name_t: string,
	desc_t: string,
	cost: number,
	prerequisite: string?, -- 初始化阶段将 "" 规范化为 nil
	padName: string,
}
```

**公开查询接口：**

| 函数签名 | 用途 |
| --- | --- |
| `GameData.GetPersonalUpgradeOrder(): { UpgradeCategory }` | 返回固定顺序 `{ "moveSpeed", "runeBatch", "sellBonus", "weapon", "carryTool" }` |
| `GameData.GetUpgradeCost(category: string, level: number): number?` | 统一查询 5 条个人升级线任意等级的价格（无该类别或越界返回 `nil`） |
| `GameData.GetMaxUpgradeLevel(category: string): number` | 查询指定升级线的最大等级（取代 `#Config.PersonalUpgradeCosts[category]`） |
| `GameData.GetWeaponByLevel(level: number): WeaponConfig` | 按等级取武器配置（越界回退 1 级） |
| `GameData.GetWeaponById(id: string): WeaponConfig?` | 按 `W01` 等 ID 查武器 |
| `GameData.GetWeaponLevelByModel(modelName: string): number?` | 按模型名反查武器等级（用于识别装备的 `Tool`） |
| `GameData.GetAllWeapons(): { WeaponConfig }` | 按等级升序返回全部武器（供预加载等遍历） |
| `GameData.GetCarryToolByLevel(level: number): CarryToolConfig` | 按等级取背包配置（越界回退 1 级） |
| `GameData.GetCarryToolById(id: string): CarryToolConfig?` | 按 `T0`~`T4` 查背包 |
| `GameData.GetMoveTier(level: number): MoveTierConfig` | 按等级取移速配置 |
| `GameData.GetRuneBatchTier(level: number): RuneBatchConfig` | 按等级取画符批量配置 |
| `GameData.GetSellBonusTier(level: number): SellBonusConfig` | 按等级取售价加成配置 |
| `GameData.GetFacility(facilityId: string): AutomationFacilityConfig?` | 按 `A00`~`A05` 查自动化设施 |

### 4.4 多语言无缝衔接说明

1. `LocalizationExtension.lua` 会同时抓取：
   - `GameTexts.luau` 中的 UI/交互/提示/战斗/通知词条；
   - `GameConfig` 下 4 张子数据表中所有 `_t` 字段（`WeaponData.name_t`、`CarryToolData.name_t`、`AutomationFacilityData.name_t`、`AutomationFacilityData.desc_t`）。
2. 由于这 23 条名称/描述从 `GameTexts.luau` 移除并唯一保留在数据表 `_t` 列：
   - 不会出现同一文本被两处重复抓取的情况；
   - `AutomationRules.DescribePrereq`（`REQUIRES: {1}`）与解锁广播 `FacilityUnlocked`（`{1} UNLOCKED {2}`）中的设施名，由 `ProcessingTextTool` 直接对 `prereq.name_t` / `facility.name_t` 执行 `TranslationTool.Translate(label, source)` 后填回 `{1}` / `{2}`，保持动态多语言刷新能力；
   - 策划后续在 Excel 新增 `W07` 或修改设施描述时，只需运行 `BAT → 读取Json数据 → 抓取新翻译文本`，业务代码零修改。
