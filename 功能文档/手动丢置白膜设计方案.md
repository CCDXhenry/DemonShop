# 手动丢置白膜设计方案

> 来源：2026-11-23 设计访谈（grill-me）结论。抛物线预览参考 `C:\Users\herong\Desktop\work\Throw\Scripts`（只读，不修改参考项目）。

## 1. 目标

玩家扛着白膜时可以瞄准后手动丢出。白膜落稳后，如果实际位置在 SoulHoldingPool 区域内，就算存入存放池；否则作为普通落地白膜留在原地。

## 2. 交互

| 端 | 操作 |
| --- | --- |
| PC | 扛着白膜时按住鼠标左键开始瞄准，显示轨迹；松开左键丢出。水平方向取鼠标所在的屏幕射线（与 Throw 一致，不读取垂直视角） |
| 移动端 | 扛着白膜时，`TouchAttackFrame` 原位置的攻击钮切换为丢置摇杆（新模板 `ReplicatedStorage.UI.ThrowStick`）。轻点按镜头前方丢出，拖动摇杆调整方向，拖出死区后再回到中心表示取消 |
| Q 键 | **移除**原有“原地放下”（客户端输入和服务端 `Drop` 请求入口都删除）。角色死亡、离场、坠落等系统释放仍使用 `Carry.Drop` |
| E 键（池） | **保留**：靠近池边按 E 放入（StoreBody），空手按 E 取出，行为不变 |

- 扛着白膜时左键原本不触发攻击（`Attack` 已经因为 `Held` 而失败），丢置不和攻击冲突。
- 正在画符、打开窗口、角色死亡或冷却未结束时不能开始瞄准；输入被取消、角色重生或失去焦点时取消瞄准。

## 3. 丢哪一具

- 每次丢出肩上**最顶层**的一具（`Carried(player)[1]`，和原来 Q 键的选择一致），剩下的自动 `Restack`。只剩最后一具时，丢出后恢复装备棍棒。
- 已画符（Painted）的白膜也可以丢，但落进池区**不会入池**，按 Ground 处理。

## 4. 弹道与预览

- **标准斜抛抛物线**：出手点在肩部前方，固定仰角，固定水平距离；在共享模块里由水平方向算出初速度：
  - `p(t) = origin + v0·t − ½·g·t²·ŷ`
  - 根据水平距离 `R` 和仰角 `θ` 求出 `v0`（考虑出手高度与落点高度差时，以平地为基准求初速，实际落点由扫掠确定）。
- 初始参数（集中写在 `PhysicsConfig.ManualThrow`，方便调整）：
  - `RangeStuds = 18`，`AngleDegrees = 35`，`CooldownSeconds = 0.35`
  - 出手点偏移（肩部前方）、预览采样步长、最长预览时长、白膜扫掠盒尺寸、Beam 宽度、虚线数量和透明度、合法/警告颜色
- **预览视觉**沿用 Throw：两段虚线 Beam 加落点光圈。斜抛的加速度不变，所以两段 Beam 以轨迹中点切分，各自拟合一段 Bezier（`BeamCurve` 思路）。
- **落点颜色**：落点满足入池条件时显示绿色，否则显示黄色。入池条件：在 PoolContains 严格区域内、白膜未画符、池未满。
- 模板：`ReplicatedStorage.Models.ThrowAim`（含 `AimArc` 两段 Beam 和 `Ring` 光圈），由 `Tools/Gameplay/build-game-assets.luau` 在 Edit 模式增量生成。

## 5. 服务端权威与飞行

1. 客户端发送请求 `{ action = "Throw", target = 顶层白膜 id, version, direction = 水平方向 }`。
2. 服务端校验：玩家存活、未在画符、目标是该玩家顶层白膜且版本一致、方向有限且非零（只取水平分量）、冷却已结束。
3. 服务端按共享公式**重算**抛物线，用体积扫掠（Blockcast，排除角色和白膜自身）求出落点 CFrame。
4. 飞行段**复用现有 PoolToss 机制**：
   - 扩展 `Types.PoolToss`，增加 `kind: "Pool" | "Manual"`，以及 `origin`、`velocity`、`duration` 字段，用于描述抛物线。
   - 新增 `Carry.BeginManualToss(item, origin, velocity, duration, target, thrower, restoreTool)`：Detach 后设为 Loose，抛掷者持有物理所有权，飞行时关闭碰撞，并设置 ReleaseContacts。
   - 客户端 `WhiteBodyPresentationManager.DrivePoolToss` 遇到 `kind == "Manual"` 时按抛物线公式驱动（原来是 Bezier 弧线），到达落点后交给物理继续下落。
5. 到达落点后恢复碰撞，布娃娃自然落稳（沿用 `AdvanceToss` 的落稳/超时判定，地面参考改为实际落点）。

## 6. 入池判定

落稳后，取白膜 `UpperTorso` 的实际位置判定：

| 条件 | 结果 |
| --- | --- |
| 在 `Scene.PoolContainsStrict` 内，且 `stage ~= "Painted"`，且 `#pool < PoolCapacity` | 入池：`location = "Pool"`，加入 `self.pool`，`AnchorPool` |
| 在池区内但池已满 | 按 Ground 处理，并向抛掷者提示 `PoolFull` |
| 在池区内但已画符 | 按 Ground 处理 |
| 不在池区内 | 按 Ground 处理（与 `Carry.Drop` 落地后的状态一致，可重新拾取） |

- `Scene.PoolContainsStrict`：取 PoolFloor 的水平范围，**不加** 1.5 外扩边距，高度到围墙顶。原 `PoolContains`（带边距）继续用于池内越界回收，不受影响。
- 飞行期间白膜的 `location` 设为 `"Thrown"`（新值）：不能被拾取，不计入池容量。落稳后再切换为 Pool 或 Ground，并 `version += 1` 广播。
- 抛掷者在飞行中离场：沿用 AdvanceToss 无抛掷者分支，直接放到落点再判定。

## 8. 反馈与范围

- 不新增音效和动画资产。出手与入池复用 GameSoundTool 中已有的放入、落地类音效，没有合适的就静音。
- 不启动 Play。脚本只改本地文件，通过 Script Sync 同步；模板只在 Edit 模式下由构建器生成。
- 验收：strict 检查改动文件、`test_rules.py`、`check_foundation_contracts.py`；实机验证需要用户授权后再进行。
