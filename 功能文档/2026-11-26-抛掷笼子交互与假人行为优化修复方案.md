## 二、逐项详细规格与实现指导

---

### T1：两处笼子真实物理防弹出（单向空气墙 + 撞击发亮特效）

#### 1. 现状与根因
- `Scripts/ReplicatedStorage/Scripts/Shared/PhysicsConfig.luau` 中 `ManualThrow` 的飞行物理弹性偏高（`FlightElasticity = 0.42`、`FlightElasticityWeight = 2.0`），白膜带着较高水平初速和旋转速度砸入 `SoulHoldingPool` 或 `FastChuteLanding` 后，极易反弹越过矮围栏（`Curb` 仅 0.7 stud 高）。
- `Scripts/ServerStorage/Scripts/ProcessingManager.luau`（约 L2540~L2560）检测到 `Pool` 或 `Chute` 内白膜超出边界后，会直接将其降级为 `Ground` 状态。

#### 2. 已确认设计决策
- **统一适用范围**：地下室手动存放池（`SoulHoldingPool`）和楼下快投落料区（`FastChuteLanding`）两处统一处理。
- **保留真实物理**：不使用强磁吸传送锁死，必须保留真实物理弹跳与堆叠手感。
- **单向放行 + 碰撞组切换**：
  1. 玩家角色始终不与笼子空气墙发生碰撞，可自由走入笼子拾取白膜。
  2. 白膜在**笼子外部飞行**时，其碰撞组不与笼子空气墙碰撞，确保从外部任意合理角度往笼子里抛都不会被空气墙挡在外面。
  3. 白膜一旦**进入笼子内部判定体积**，服务端立即将其切换至“笼内白膜”碰撞组（与笼子空气墙发生真实物理碰撞），并可适度降低落地后的弹性参数（如切回低弹性 `GroundElasticity` 或阻尼衰减），使白膜撞到笼子空气墙时真实弹回笼内、绝不飞出。
  4. 当玩家靠近拾取笼内白膜（状态转为 `Carried`）时，恢复常规碰撞组。
- **空气墙撞击发亮特效**：
  - 空气墙平时完全不可见（`Transparency = 1`）。
  - 当白膜在笼内撞击空气墙（或被阻挡反弹）时，在对应墙面/撞击点触发能量护盾/空气墙发亮反馈（短暂高亮并平滑淡出），清晰传达“空气墙挡住了白膜”的视觉反馈。

#### 3. 实现要点（实机复测重构版）
- **碰撞组（`PhysicsService`）**：
  - 区分 `RagdollBodies`（常规/笼外白膜）、`CageContainedBodies`（笼内白膜）与 `CageAirWalls`（笼子空气墙）。
  - 碰撞矩阵：`CageAirWalls` **仅与** `CageContainedBodies` 碰撞；与玩家默认组、`RagdollBodies` 均不碰撞。
- **收拢并加厚空气墙（消除牢房夹缝与四角凸出）**：
  - 实测 `SoulHoldingPool` 内部 `laofang` 实体围栏/角柱占内侧 `0.3~1.25 studs`（四角 `Cornerstone` 到 `±10.75 / ±6.75`）、`FastChuteLanding` 实体 `Curb` 占内侧 `0.69 studs`。
  - `CageGeometry.Walls` 支持 `inset` 与 `WallThickness = 2` studs：`SoulHoldingPool` 内收 `PoolWallInset = 1.3`（净空内壁 `±10.70 × ±6.70`，彻底包覆四角 `Cornerstone`），`FastChuteLanding` 内收 `ChuteWallInset = 0.8`（净空内壁对齐 `CushionPad` 边沿），厚墙向外完全包覆实体围栏，消除一切夹缝与贴角弹跳。
  - 空气墙材质设为强吸能零弹性（`Elasticity = 0, ElasticityWeight = 100, Friction = 0.85`），白膜落地材质设为 `GroundElasticity = 0, GroundFriction = 0.9, GroundJointFrictionScale = 1.35`，撞墙顺滑落底不再来回反弹。
  - 同步更新 `Tools/Gameplay/build-game-assets.luau`、`Tools/Gameplay/build-automation-assets.luau` 及 Studio Edit 场景。
- **客户端全程物理所有权 + 服务器仅做复制与权威收纳（彻底消除抽搐）**：
  - 抛掷者客户端（`thrower`）全程持有白膜 `NetworkOwner` 跑 60fps 纯本地物理（飞行、进笼、撞墙、松弛堆叠），由引擎自动向服务器与其余客户端复制姿态。
  - `WhiteBodyPresentationManager` 在客户端本地进入净空瞬间一次性预切 `CageContainedBodies` 碰撞组、零弹性高阻尼材质与水平速度衰减（`EntryHorizontalDamping = 0.45`、上限 `14 studs/s`）。
  - 服务端 `Carry.Contain` / `FinishPool` / `FinishChute` / `AdvanceManualToss` 在抛掷者在线时**绝不抢回 `NetworkOwner`、绝不二次修改速度、绝不用 `PivotTo` 强行拉扯**，仅同步权威位置/收纳状态（仅当抛掷者离线时才由服务端兜底接管）。
- **稳定瞄准抛物线 + 池底投影预览（解决抛物线乱动）**：
  - `ManualThrowController` 键鼠瞄准方向锁定为镜头正前方水平朝向（`self.forward`），并与服务端 `ProcessingManager.Throw` 统一改用稳定的 `HumanoidRootPart.CFrame`（`HeightStuds = 1.0`）作为出手起点，消除自由光标与呼吸/肩扛晃动。
  - `CageGeometry.IntersectInnerWall` 在 `ThrowAimPreview` 中拦截对侧收拢内壁时，将落点圆盘向下投影平贴在池底地面（法线朝上），消除圆盘在半空竖墙与池底之间的跳变。
- **客户端发亮特效节流**：
  - `ProcessingManager.BindThrowBarriers` 在 `wall.Touched` 增加最小撞击速度阈值（`ImpactMinSpeed = 3.5`）与 `ImpactCooldown = 0.22s`，避免白膜贴墙静止时反复闪亮。

#### 4. 验收标准
- 从笼子外各个方向向 `SoulHoldingPool` 和 `FastChuteLanding` 抛掷白膜，不会在进笼前被空气墙挡在外面。
- 白膜落入笼子后，即使高速撞壁也会被真实物理弹回笼内，不弹飞出笼；撞壁瞬间对应空气墙面触发明显发亮特效并平滑消失。
- 玩家可无阻挡自由走进/走出两处笼子。

### T2：楼上快投洞口导流防偏（解决扔不进洞与掉出楼下笼子）

#### 1. 现状与根因
- `Tools/Gameplay/build-automation-assets.luau`（L661~L670）中的 `ChuteThrowBaffles`（`West`、`East`、`Back` 三面挡板）目前设置为 `CanCollide = false`、`CanQuery = true`，仅用于客户端抛掷预览射线，真实物理飞行时完全不起阻挡作用。
- 玩家在楼上向洞口抛掷时，白膜容易直接飞越洞口或擦边卡在洞口外沿；即使落入洞口，高速砸向楼下 `FastChuteLanding` 时，也会因水平动量与高弹性弹飞出楼下笼子。

#### 2. 已确认设计决策
- 楼上洞口 `ChuteThrowBaffles` 三面挡板改为**仅阻挡白膜的真实物理碰撞**（玩家可自由穿过），并在白膜撞击挡板时触发同样的**空气墙发亮特效**。
- 挡板配合洞口形成真实物理导流漏斗，确保玩家大致朝洞口方向抛掷即可顺滑撞板落入竖井，再落入楼下 `FastChuteLanding` 并由 T1 的空气墙稳稳兜住不掉出。

#### 3. 实现要点
- **碰撞组设置**：
  - 将 `ChuteThrowBaffles`（以及必要时补充竖井内壁防卡边斜坡/护壁）设为专门碰撞组 `ChuteBaffleWalls`（仅在 A00 `FastChute` 解锁后启用 `CanCollide = true`）。
  - `ChuteBaffleWalls` 与 `RagdollBodies` 及 `CageContainedBodies` 碰撞，与玩家默认组不碰撞。
- **挡板几何与高度检查**：
  - `ChuteThrowBaffles` 厚度增至 `1.2 studs`、底部与楼板重合 `0.5 stud`（`BaffleFloorOverlap = 0.5`），消除洞口边缘缝隙。
  - 在 Studio Edit 模式下核对 `FastChuteOpening`、`ChuteThrowBaffles` 与楼下 `FastChuteLanding` 的垂直对齐关系，确保三面挡板覆盖抛物线最高点（`noodlesFloorYMax` 至天花板附近），无底部缝隙导致白膜卡在楼板边缘。
  - 若洞口边缘容易卡住布娃娃四肢，可微调挡板内收或添加低摩擦竖井内衬。
- **楼下衔接**：
  - 白膜穿过竖井进入楼下 `FastChuteLanding` 区域时，立即触发 T1 的 `CageContainedBodies` 碰撞组切换与低弹性切换，防止从 20 studs 高处砸落反弹冲出笼外。
- **未解锁 A00 保护**：
  - `FastChuteCover` 未解锁前，挡板不启用阻挡或保持隐藏；解锁 A00 时在 `ProcessingManager.ApplyFacilityWorldState` 中同步启用 `ChuteThrowBaffles` 碰撞。

#### 4. 验收标准
- 解锁 A00 后，在楼上面向洞口不同角度和站位抛掷白膜，撞到洞口三面挡板时挡板发亮，白膜真实物理弹落进洞。
- 白膜从楼上掉入楼下 `FastChuteLanding` 后，稳稳留在楼下笼子内并完成 `Chute` 收纳，不弹飞、不卡洞口。
- 玩家在楼上洞口周边移动不受透明挡板阻挡。

### T3：取消笼子统一「取出」按钮，改为靠近具体白膜拾取

#### 1. 现状与根因
- `Scripts/ReplicatedStorage/Scripts/Shared/WorldInteractionRules.luau`：
  - L45~L48：`Pool` 锚点在玩家空手且 `snapshot.pool > 0` 时生成 `TakeSharedBody` 取出按钮。
  - L73~L75：`ChutePickup` 锚点在 `snapshot.chuteQueue > 0` 时生成 `TakeChuteBody` 取出按钮。
  - L83~L85：单个物品拾取条件仅允许 `item.location == "Ground" or (item.location == "Street" and item.hits >= Config.StunHits)`，`location == "Pool"` 和 `location == "Chute"` 的白膜**不会**挂载拾取提示。

#### 2. 已确认设计决策
- **删除两处笼子的统一「取出」按钮**：
  - `Pool`（`SoulHoldingPool`）不再在空手时显示 `TakeSharedBody` 按钮。
  - `ChutePickup`（`FastChuteLanding`）不再显示 `TakeChuteBody` 按钮。
- **保留「存入/投放」与画符台快捷取用**：
  - 扛着未画符白膜靠近 `Pool` 时，保留 `StoreBody` 存入按钮。
  - 扛着未画符白膜靠近楼上 `Chute` 洞口时，保留 `DepositBodies` 投放按钮。
  - 空手靠近画符台 `Table` 时，保留 `FetchAndPaint`（从池中直接取一具开画）的快捷操作。
- **靠近笼内具体白膜直接拾取**：
  - 玩家走进 `SoulHoldingPool` 或 `FastChuteLanding`，靠近里面的任意一具白膜即可直接出现拾取提示（`PromptPickUp`），按 E 扛起。

#### 3. 实现要点
- **`WorldInteractionRules.luau`**：
  - `Pool` 分支：移除 `elseif not carrying and snapshot.pool > 0 then action = "TakeSharedBody" end`。
  - `ChutePickup` 分支：移除该分支（或始终返回 `nil`）。
  - 单体物品 `else` 分支：将 `reachable` 条件扩展为允许 `item.location == "Pool"` 和 `item.location == "Chute"`（前提 `item.kind == "Body"`、`not item.holder`、`not load.other`）。
- **`ProcessingManager.luau`（服务端拾取权威处理）**：
  - 在处理单个白膜拾取（`Interact` -> target 为 `item.id`）时，允许拾取 `location == "Pool"` 和 `location == "Chute"` 的白膜：
    - 若原 `location == "Pool"`：从 `self.pool` 数组中移除该 `item.id`，更新 `stationVersions.Pool`，若存在 `poolOverflowCount > 0` 则调用 `ReplenishPoolVisible()`。
    - 若原 `location == "Chute"`：从 `self.chuteVisible` 数组中移除该 `item.id`，递增 `chuteTakeSerial` 并更新 `stationVersions.ChutePickup`，若存在 `chuteOverflowCount > 0` 则调用 `ReplenishChuteVisible()`。
  - 调用 `TakeBody` 扛起时，同步将白膜碰撞组从 `CageContainedBodies` 恢复为常规肩扛/无碰撞状态。
  - 检查服务端距离/视线校验（`Near` / `Scene.Visible`），确保笼子透明空气墙不会遮挡 `Scene.Visible` 射线（将空气墙设为 `CanQuery = false` 或在射线过滤中排除）。

#### 4. 验收标准
- 空手靠近地下存放池和楼下快投区时，不再出现笼子的统一“取出”提示按钮。
- 扛着白膜靠近存放池与楼上洞口时，“存入 / 投放”按钮仍正常显示并可用；空手靠近画符台仍可快捷取用。
- 玩家走进任意一处笼子，靠近其中某具白膜即可显示该白膜的拾取提示，成功拾取后队列计数与自动化逻辑（如 `AutoRune` 取料）不产生幽灵引用或报错。

### T4：拾取白膜改为点按 E（取消长按转圈）

#### 1. 现状与根因
- `WorldInteractionPrompt` 模板默认 `HoldDuration = 0.5`（见 `build-game-assets.luau` L525、`build-automation-assets.luau` L124）。
- **关键代码约束**：`Scripts/ReplicatedStorage/Scripts/Client/WorldInteractionManager.luau`（L123~L142）目前强依赖长按事件链路：`PromptButtonHoldBegan` 设置 `binding.holding`，`Triggered` 里校验 `if not holding then return end`。在 Roblox 引擎中，当 `ProximityPrompt.HoldDuration == 0` 时，**不会触发 `PromptButtonHoldBegan`**，若只改 `HoldDuration = 0` 会导致按 E 完全无响应！

#### 2. 已确认设计决策
- **适用范围**：**仅拾取白膜**改为点按（`HoldDuration = 0`），包括街道击晕的白膜、地上掉落的白膜、以及 T3 中笼子（`Pool` / `Chute`）内的白膜。
- **保持现状范围**：拾取药水、以及所有工位交互（画符台、祭坛、存入池子、货架取药水、法阵提交等）保持原有 `0.5s` 长按转圈不变。

#### 3. 实现要点
- **`WorldInteractionRules.luau`**：
  - 在 `Action` 类型中新增可选/布尔字段（如 `instant: boolean?` 或 `holdDuration: number?`），仅当解析结果为拾取白膜（`action == "PromptPickUp"` 且 `object == "PromptBody"`）时标记 `instant = true`（`holdDuration = 0`），其余保持默认（`0.5`）。
- **`WorldInteractionManager.luau`**：
  - 在 `Refresh` 更新 `binding` 时，根据 `action.instant` 动态设置 `binding.prompt.HoldDuration = if action.instant then 0 else defaultHoldDuration`（从模板读取默认时长 0.5）。
  - 修改 `prompt.Triggered` 回调逻辑：
    - 若当前 `prompt.HoldDuration <= 0`（点按模式）：不要求 `binding.holding ~= nil`，直接用 `current = self:Resolve(target)` 校验 `prompt.Enabled`、`current ~= nil` 且 `current.signature == binding.signature`，通过即发 `Net.FireRequest({ action = "Interact", target = current.target, version = current.version })`。
    - 若 `prompt.HoldDuration > 0`（长按模式）：保留原有 `binding.holding` 一致性校验，防止长按中途状态变化误触发。
  - 同时确认移动端触控点击该 Prompt 也能即时响应。

#### 4. 验收标准
- 靠近街道击晕白膜、地面白膜、笼内白膜时，按一下 E（无转圈等待）立刻扛起。
- 拾取地上药水、以及所有工位交互（画符台、祭坛、存放池存入、召唤阵提交等）仍保持 `0.5s` 长按转圈。
- 快速连按 E 拾取多具白膜时，不会因状态变更或并发请求出现卡死或漏响应。

### T5：假人逛街区域调整（Studio 可视化区域块配置）

#### 1. 现状与根因
- `Scripts/ServerStorage/Scripts/Scene.luau`（L304~L309）的 `Scene.StreetPoint(random)` 直接在 `Scene.Deck`（`Raised Street Deck With Stair Void -> Box_005`）单一矩形上缩进 4 studs 随机采样。
- `Scripts/ServerStorage/Scripts/NPC.luau`（L147~L154）的越界检测也只判断 `Scene.Deck` 矩形范围，导致假人经常走到楼梯口、店铺门口、边缘死角等不合理区域。

#### 2. 已确认设计决策
- 在 Studio 场景 `Workspace.NeonContractDistrict` 下新增可视化区域配置目录 **`StreetWalkZones`**（内含一个或多个透明、不可碰撞的 `BasePart` 区域块，支持多块矩形拼接覆盖街道主干道）。
- 默认初始布局先按街道实际通行区摆放，避开楼梯洞口、店铺内部/门口及边缘死角；后续策划/美术可直接在 Studio Edit 模式拖拉、增删区域块微调，无需修改代码。

#### 3. 实现要点
- **Studio 场景结构**：
  - 在 `Workspace.NeonContractDistrict` 下创建 `Folder`：`StreetWalkZones`。
  - 内部放置若干命名为 `Zone_1`、`Zone_2`... 的 `Part`（`Anchored = true`、`CanCollide = false`、`CanQuery = false`、`CanTouch = false`、`Transparency = 1`；编辑期可用半透明色预览，发布/运行时隐形或由服务端启动时自动设 `Transparency = 1`）。
  - Edit 阶段需先检查 `NeonContractDistrict` 实际几何坐标，合理布设初始区域块（覆盖主街道、避开楼梯口与障碍物）。
- **`Scene.luau` 采样与查询 API**：
  - 启动时扫描 `NeonContractDistrict:FindFirstChild("StreetWalkZones")` 下的所有 `BasePart`（若缺失则安全回退到原 `Scene.Deck`，保证离线单测与兼容）。
  - **按面积加权随机采样** `Scene.StreetPoint(random)`：根据每个区域块 `Size.X * Size.Z` 的面积占比抽取一个区域块，再在其局部 XZ 内采样，并向下射线（`Raycast`）对齐真实街道地面高度。
  - **区域包含判断** `Scene.IsInStreetWalkZones(position: Vector3, margin: number?): boolean`：判断坐标是否落在任一 `StreetWalkZones` 区域块的水平（及合理高度）范围内。
  - **区域最近安全点/边界法线** `Scene.ClampToStreetWalkZones(position: Vector3)` 或方向修正辅助函数，供 T6 逃跑时遇边界折返使用。
- **`NPC.luau` 接入**：
  - `NPC.Spawn`：使用新的 `Scene.StreetPoint(random)` 采样，并保留防重叠检测。
  - `NPC.Update`：越界拉回条件由原 `Scene.Deck` 边界切换为 `not Scene.IsInStreetWalkZones(root.Position, tolerance)`（保留一定的容差避免边缘频繁瞬移）。

#### 4. 验收标准
- 假人仅在 `StreetWalkZones` 划定的区域内刷出和闲逛，不再走进楼梯口、店铺门口或边缘死角。
- 在 Studio Edit 模式下拖动或增删 `StreetWalkZones` 内的 `Part` 后，无需改代码，假人刷出与逛街范围自动随之更新。

### T6：假人逛街动作与受击逃跑升级（慢走、来回看、高压力逃跑）

#### 1. 现状与根因
- `Scripts/ServerStorage/Scripts/NPC.luau`：
  - 当前移动速度为 `WalkSpeed = 7`，偏快且缺乏悠闲逛街感。
  - 停顿期间仅播放静态 `IdleAnimation`（35% 概率停 0.6~1.2 秒），没有“来回看”的张望动作。
  - `NPC.Hit` 受击后硬直 `HitStaggerSeconds = 0.75` 秒并停在原地，硬直结束后继续以速度 `7` 随机闲逛，**无任何逃跑机制**。

#### 2. 已确认设计决策
- **慢走**：日常逛街速度降至约 **`4.5 studs/s`**（行走动画播放速度随之按比例放慢，避免滑步）。
- **来回看（停顿张望）**：
  - 假人逛街停顿期间（约 1.5~3.0 秒），增加明显的“来回看”动作：优先在客户端表现层通过程序化驱动 `Neck`（及轻微 `UpperTorso`/腰部）平滑左右转头张望（同时预留动画资产替换接口）。
- **被攻击后跑开（高逃跑压力模式）**：
  - **几乎无硬直**：受击后仅保留极短的受击击退/表现反馈（如 `0.1~0.15s` 或击退同时立刻转身），不再原地罚站 `0.75s`。
  - **高速逃离**：以接近玩家常规移速的 **`15~16 studs/s`**（鼓励玩家使用冲刺或范围武器拦截；自动打手速度为 20 仍可稳定追击）朝**背离攻击者方向**逃跑。
  - **逃跑时长与边界折返**：单次受击进入惊慌逃跑状态持续约 **4~5 秒**（再次受击刷新时长）；逃跑目标点持续采样在 `StreetWalkZones` 内，若前方临近区域边界或墙体障碍，自动向区域内部安全方向折返，绝不跑出逛街区。逃跑时间结束后平复恢复为“慢走 + 来回看”。

#### 3. 实现要点
- **集中参数配置（`Scripts/ReplicatedStorage/Scripts/Shared/GameConfig/init.luau`）**：
  - 新增可调参数（避免魔数写死）：
    - `NpcStrollSpeed = 4.5`（慢走速度）
    - `NpcFleeSpeed = 15.5`（逃跑速度，15~16 区间）
    - `NpcFleeDuration = 4.5`（逃跑持续时长，秒）
    - `NpcHitStaggerSeconds = 0.12`（受击极短硬直，替代原 0.75s，或与击退同步结束）
    - `NpcLookAroundDurationMin = 1.5`、`NpcLookAroundDurationMax = 3.0`（停顿张望时长）
    - `NpcLookAroundChance = 0.45`（停顿并来回看的概率）
    - `NpcRunAnimation`（可选：优先复用标准 R15 跑步动画 `rbxassetid://507767714`，若未配置则加快行走动画倍率）
- **服务端状态机（`Scripts/ServerStorage/Scripts/NPC.luau`）**：
  - 扩展 `MotionState` 属性值：`Idle` / `LookAround` / `Walking` / `Hit` / `Fleeing` / `Down`。
  - **慢走与来回看**：
    - `NPC.Spawn` 与 `Ragdoll.SetMode(model, "Walking")` 同步将默认 `WalkSpeed` 设为 `Config.NpcStrollSpeed`。
    - 到达目标或触发停顿且进入 `LookAround` 时，设置 `MotionState = "LookAround"` 并给一个随机种子/方向属性（供各客户端表现一致的左右张望节奏），持续 `1.5~3.0s` 后再选下一个慢走点。
  - **受击逃跑**：
    - `NPC.Hit` 中：未击晕时记录 `item.fleeUntil = now + Config.NpcFleeDuration` 与 `item.fleeFrom = attackerPosition`（或沿受击方向 `direction` 背离逃跑）；将硬直缩短至极短值（`0.1~0.15s`），硬直一结束立刻切 `MotionState = "Fleeing"`、`humanoid.WalkSpeed = Config.NpcFleeSpeed`，播放快跑动画。
    - `NPC.Update` 中在 `Fleeing` 状态下高频（如每 0.25~0.4s）重算逃跑目标点：优先沿背离方向在 `StreetWalkZones` 内取前方 12~18 studs 处的安全点；若前方射线碰墙或超出 `StreetWalkZones`，按角度偏移（±45°、±90°、±135°）挑选落在 `StreetWalkZones` 内且无遮挡的最佳折返点。
    - 逃跑超时后切回 `Walking`/`Idle`，`WalkSpeed` 恢复 `Config.NpcStrollSpeed`。
- **客户端表现（`CharacterPresentation.luau` / `WhiteBodyPresentationManager.luau`）**：
  - 监听 `MotionState == "LookAround"`，在客户端 `PoseMixer` / 关节层为 `Neck`（可叠加轻微 `Waist`）叠加平滑正弦/缓动左右转头偏移（如左右 ±35°~45° 停留再转向另一侧），切换为 `Walking`/`Fleeing`/`Hit`/`Down` 时平滑归零释放控制权。
  - 在 `Fleeing` 状态下可选叠加轻微前倾姿态，强化惊慌逃跑观感。

#### 4. 验收标准
- 未受击假人以约 `4.5 studs/s` 慢走，步频自然不滑步；停顿时有清晰可见的左右转头张望（来回看）动作。
- 玩家攻击未击晕假人后，假人几乎无硬直，立刻以 `15~16 studs/s` 背离玩家方向快跑逃离，需玩家冲刺或利用范围武器拦截补刀。
- 逃跑过程中遇到障碍或 `StreetWalkZones` 边界会自然折返，不卡墙、不跑出逛街区；数秒未受击后恢复慢走状态。
- 自动打手（`Brute1` / `Brute2`）攻击与追击假人流程不受破坏。
