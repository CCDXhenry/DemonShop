> 来源：2026-11-24 `/grill-me` 设计访谈结论与代码/Studio 场景实测核对。本方案不修改 `docs/` 下任何文件。

## 1. 访谈拍板结论总览（设计取舍基线）

经过逐分支确认，当前阶段对 `docs`（v5.0 设计文档与数值表）的裁剪、改造与保留边界如下：

| 决策维度 | `docs` v5.0 原始设计 | 当前阶段拍板方案 | 状态 |
| :--- | :--- | :--- | :---: |
| **手动画符玩法** | 固定长按 `2.5s` 进度条，个人升级一次连画 `1~5` 人 | **保留现有笔刷涂抹覆盖率玩法**（含 50% 自动翻面），每次固定 1 具；**永久砍掉“一次画符人数”升级** | 裁剪改造 |
| **产出物与出售机制** | 产出 5 档“灵魂石”；顾客每 `10s` 到访一次包圆库存 | **保留“药水”包装与模型**；在提交点（`SummoningSubmitAnchor`）**即时一键卖出全部药水**（不等顾客） | 裁剪改造 |
| **存放池与药水架容量** | 牢笼无限容量，灵魂石无存储上限 | 存放池与药水架均改为**逻辑无限容量 + 有限实体显示**（池最多显示 8 具、架最多显示每档 6 瓶），解除架满卡祭坛限制 | 本期落地 |
| **自动化流水线（6 项）** | 快速通道 + 打手 1/2 号 + 自动符文台 + 自动炼化台 + 自动售货员 | **6 项全做**，解锁价格保持 `250 / 1,000 / 2,500 / 2,000 / 4,500 / 9,000`；保留物理断点，但**双线全程严格隔离**（自动机器与自动售货员绝不消耗手动线池子与手动药水架） | 本期落地 |
| **快速通道与解锁底盘圈** | 街心投料箱 `0.5s` 滑落 `-1F` | **`A00 快速通道` 在 `NewShop_Noodles` 店内置放底盘圈模型并挂载 GUI（显示功能说明与价格）**，玩家踩上满足条件即**自动解锁并开启直通 `AutoHole` 的空洞**（支持按 E 倒入、斜抛落入、玩家跳洞下楼）；**后续 `A01~A05` 统一在对应机器正前方创建底盘圈模型+GUI** | 本期落地 |
| **单局数值匹配** | 普通市民 `10 DC`，配合街区扩建（最高 `600 DC`）与出售加成 | 因本期不存档且暂不做街区/个人加成，**单瓶药水保持 `100` 金币**（全套自动化 `19,250` 金币约合 `193` 瓶，单局 15~25 分钟可完整闭环） | 本期适配 |
| **数据存档范围** | 个人资产独立持有，公共设施全队共享，无离线收益 | **当前阶段所有玩法数据均不存档**（金币、公共解锁仅本局有效，进服归零，关服重置；基础框架的设置与登录统计照常保留） | 本期不存 |
| **板块 01：个人升级** | 武器 `W01~W06`、搬运 `T0~T4`、移速、画符人数、出售加成 + 随身商店 | **本阶段全部暂缓**（保持单把近战武器 `3` 击晕、现有肩扛人体塔堆叠 + E 键拾取 + 左键瞄准抛投、默认移速、无随身商店） | 延后阶段 |
| **板块 03：街区扩建** | 街区 `Lv.1~Lv.4` 踩踏扩建，刷新 `P101~P105` 五阶行人 | **本阶段暂缓**（维持默认普通市民刷新池与现有完整霓虹街景；街区升级与多阶固定击晕次数行人留待下一阶段） | 延后阶段 |

**双线严格隔离原则**：地下南侧手动线（`SoulHoldingPool` → `RuneBodyTable` → `SoulConversionAltar` → `SoulCrystalDisplay`）与地下北侧自动线（`FastChute/AutoHole` → `AutoPaint` → `AutoCook` → 自动药水架 → `AutoClerk`）全程物理与逻辑隔离。自动符文台只吸取 `AutoHole` 落料，自动售货员只搬运 `AutoCook` 旁自动药水架库存，绝不触碰手动线资产。

### 2.2 架构、存档与场景空间对比

1. **存档与会话状态（`ServerGameInfo.luau` / `GameConfig.luau`）**：
   - **现状**：`PlayerSaveInfo.coins` 会持久化写入 DataStore，跨局保留金币；加工场景状态仅本局内存持有；没有任何房间公共解锁状态或个人升级字段。
   - **本期差异处理**：遵循“当前所有玩法数据不存档”决议，保留基础框架 `ServerGameInfo` 契约与设置/登录统计存储，但玩家进服时金币会话归零（不从 DataStore 继承历史金币），房间公共解锁表挂在 `ProcessingManager` 内存实例上，随服务器生命周期生灭。
2. **场景结构与 Studio 实测坐标（`PlaceId: 110812537538556`）**：
   - **现状已具备双层结构**：上层街道 `deck` 位于 `Y ≈ 20.0~20.3, Z ∈ [-96, -39]`，西侧通过 `StairEntranceHouse (-76, 24.7, -38.6)` 与 `service` 楼梯下达下层地下工坊 `enclosure`（地面 `Y = 0, Z ∈ [-19, +53]`）。
   - **手动线位于地下南侧（`Z ≈ +24`）**：`SoulHoldingPool (-39.8, 2.5, 23.2)` → `RuneBodyTable (-14.2, 4.6, 24.1)` → `SoulConversionAltar (11.1, 4.6, 26.5)` → `SoulCrystalDisplay (28.2, 4.6, 25.8)` → 东侧提交点 `SummoningSubmitAnchor (65.2, 1.6, 12.6)`。
   - **自动线目前仅有 3 组无逻辑灰盒 Part（位于地下北侧 `Z ≈ -11`，正对手动线）**：
     - `Workspace.AutoHole`：`pos = (-47.0, 0.5, -10.0), size = (10, 1, 10)`；其正上方被 `SouthFoundation_Side (Y = 19.0, size = 160×2×80)` 封死，北侧紧邻上方商铺 `BAR_5`（后墙 `Z = -19.0`）与 `NewShop_Noodles`（后墙 `Z = -21.4`）以及空气墙 `PerimeterJumpBarrier (Z = -17.0)`；
     - `Workspace.AutoPaint`：主体 `(-19.0, 5.0, -11.0)` + 侧垫 `(-28.6, 1.5, -11.0)`；
     - `Workspace.AutoCook`：主体 `(-1.0, 5.0, -11.0)` + 进料台 `(-10.0, 3.9, -11.0)` + 右侧三层药水架板 `(10.0, 0.5/3.9/7.9, -15.0)`。
   - **完全缺失项**：快速通道竖井开口与商铺入口、6 个自动化正式模型、6 个 Tycoon 踩踏解锁垫、打手 1/2 号 AI、自动符文/自动炼化状态机、自动售货员 AI。

## 3. 当前项目实现阶段方案（M1 ~ M4 分步交付）

### 阶段 M1：本局化经济、无限容量底座与一键全卖

1. **金币与状态纯本局化**：
   - 在 `GameConfig.luau` 新增开关 `SessionOnlyEconomy = true`；
   - `ServerGameInfo.luau` 在会话初始化时将运行期 `playerInfo.coins` 置 `0`，且保存快照写入 DataStore 时金币固定归零（保留 `settingInfo`、`loginDays`、`gameTime` 等基础框架契约及 `check_foundation_contracts.py` 门禁完全通过）。
2. **存放池与药水架“逻辑无限 + 视图限流”重构**：
   - **存放池 (`SoulHoldingPool`)**：移除 `#self.pool >= Config.PoolCapacity` 的存入拦截（包括按 E 存入与斜抛入池）；新增 `PoolVisibleLimit = 8`，前 8 具生成/保留池内锚定白膜模型，第 9 具起回收实体模型并累加虚拟计数 `poolOverflowCount`；消耗池内实体后若可见数不足 8 具且 `poolOverflowCount > 0`，自动补生实体。
   - **手动药水架 (`SoulCrystalDisplay`)**：移除 `QualityCount >= ShelfCapacity` 对祭坛完成献祭的 `altarHeld` 挂起拦截；药水架改为计数账本，场景托位最多渲染 `ShelfVisibleLimit = 6` 个瓶身实体并显示真实总瓶数。
   - **全局实体上限解耦**：`MaximumBodies = 32` 仅统计世界中实际存在的白膜 `Model` 实例数，虚拟计数不占实体配额，防止囤货卡死街道刷怪。
3. **提交点一键全额出售**：
   - 改造 `ProcessingManager.Submit`：玩家靠近 `SummoningSubmitAnchor` 交互时，自动汇总并一次性扣除该玩家手持及 `Backpack` 内所有 `Potion` 堆叠总数 `N`；
   - 结算金额 `totalReward = N * Config.PotionReward`（单瓶 `100` 金币），遍历当前服务器所有活跃玩家一次性发放。

### 阶段 M2：`NewShop_Noodles` 空洞机关、正式自动化模型与机器前底盘圈构建

1. **`NewShop_Noodles` 店内快速通道解锁与动态开启空洞**：
   - **空间连通**：玩家从街道正门（`X ∈ [-62.2, -55.9], Z = -39.4`）走入 `NewShop_Noodles`，打通店内东后侧延伸内室至 `AutoHole` 正上方井口 `(X = -47.0, Z = -10.0)`（净空洞口 `8 × 8 studs`：`X ∈ [-51, -43], Z ∈ [-14, -6]`）；将下方 `StreetUpgrade.SouthFoundation_Side (Y = 19.0)` 围绕该区域拆分为四块拼接板预留通孔，并调整 `PerimeterJumpBarrier` 绕开店内后室边界；
   - **未解锁态（完整平地 + 底盘圈）**：未解锁 `A00` 时，井口位置由与店内地板齐平的封盖板闭合（无空洞），封盖板上方放置 **`A00 快速通道` 底盘圈模型**，挂载 GUI 显示解锁功能说明与价格（`250 金币`）；
   - **解锁态（出现空洞）**：玩家踩上底盘圈且满足条件（`coins >= 250`）后**立即自动扣款解锁**，移除底盘圈与封盖板，**原地出现垂直空洞**直通地下 `AutoHole (-47.0, 0.5, -10.0)` 缓冲垫；此后支持**靠近按 E 整批倒入、左键瞄准斜抛落入空洞、以及玩家直接跳洞快速下达地下工坊**。
2. **地下北侧自动化设施模型替换（`NeonContractDistrict.AutomationLine`）**：
   - 移除临时灰盒 `AutoHole`、`AutoPaint`、`AutoCook`，在原对应位置生成正式模块化设施模型与标准锚点：
     - `FastChuteLanding (-47.0, 0.5, -10.0)`：地下缓冲落料台 + 承接上方 `NewShop_Noodles` 空洞的导流护圈；
     - `BrutePost`：`NewShop_Noodles` 店门侧方的打手召唤底座；
     - `AutoRuneMachine (-19.0, 4.5, -11.0)`：自动符文刻印台 + 出料断点垫 `(-28.6, 1.0, -11.0)`；
     - `AutoSmelterMachine (-1.0, 4.5, -11.0)`：自动炼化熔炉 + 进料导轨 `(-10.0, 3.9, -11.0)` + 右侧自动药水暂存架 `(10.0, 0.5~7.9, -15.0)`；
     - `AutoClerkStation (22.0, 1.0, -11.0)`：自动售货员调度台。
3. **统一的解锁底盘圈模型（`UnlockPad`）+ 挂载 GUI（对应机器正前方就位）**：
   - `ReplicatedStorage.Models.UnlockPad` 模板：圆形底盘圈模型 + 挂载 `BillboardGui`（遵循 `roblox-ui-system` 描边 `ScaledSize` 规范，显示设施名称、功能说明、前置条件与价格，呈灰/红/绿三态）；
   - 放置点位：`A00 快速通道 (250)` 在 `NewShop_Noodles` 店内空洞封盖板上；`A01 打手 1 号 (1,000)` / `A02 打手 2 号 (2,500)` 在打手召唤座前；`A03 自动符文台 (2,000)` 在 `AutoRuneMachine` 正前方；`A04 自动炼化台 (4,500)` 在 `AutoSmelterMachine` 正前方；`A05 自动售货员 (9,000)` 在 `AutoClerkStation` 正前方。

### 阶段 M3：踩踏即解锁并发协议与自动加工线状态机（A00 / A03 / A04）

1. **踩上即自动解锁与并发防重扣**：
   - 玩家踩入底盘圈判定范围，若满足前置依赖（`A01` 依赖 `A00`、`A02` 依赖 `A01`、`A03` 依赖 `A00`、`A04` 依赖 `A03`、`A00`/`A05` 无前置）且金币充足，**无需按键或读条，立即自动扣款解锁**，隐藏底盘圈并开启空洞/激活机器；
   - 服务端设施互斥校验防同帧双扣，解锁后全房广播横幅并同步新 `Snapshot`。
2. **三处自动断点垫“逻辑无限 + 6 实体渲染”与下游消化**：
   - `chuteQueue`（`AutoHole` 未画符队列）、`autoPaintedQueue`（`AutoPaint` 已画符队列）、`autoShelfCount`（`AutoCook` 药水计数）各自最多渲染 **6 个实体**；
   - 未接通下游时，玩家可随时按 E 从断点垫取走白膜或药水；解锁下游机器（`A03` `2.0s/具`、`A04` `2.5s/瓶`）后自动消化积压库存。
3. **斜抛预览兼容快速通道**：
   - `A00` 解锁后，上层井口纳入 `ThrowArc` 合法绿色落点判定，落稳后滑落转入 `chuteQueue`。

### 阶段 M4：AI 代理闭环（A01/A02 打手 & A05 自动售货员）与门禁验收

1. **`A01 / A02 地狱打手 1 号 / 2 号`**：
   - 街面巡逻互锁目标避免抢怪 → 击晕市民 → 抱入商铺井口（单打手 `~12s/人`，双打手 `~6s/人`），原料直入 `chuteQueue`。
2. **`A05 自动售货员`（严格双线隔离）**：
   - 仅检测并搬运 `AutoCook` 旁自动药水架库存（**不触碰手动线 `SoulCrystalDisplay`**），跑至 `SummoningSubmitAnchor` 自动全额提交，全服在线玩家各得 `瓶数 × 100` 金币。
3. **工程门禁**：
   - `pwsh -File Tools/check-strict.ps1 -All`
   - `python Tools/Gameplay/check_foundation_contracts.py`
   - `python Tools/Gameplay/test_rules.py`
