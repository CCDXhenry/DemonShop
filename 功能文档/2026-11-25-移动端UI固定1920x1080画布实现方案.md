# 移动端 UI 固定 1920×1080 画布实现方案

## 1. 背景与现状问题

按照项目 UI 规范（`.agents/skills/roblox-ui-system/SKILL.md`），所有屏幕 UI 应以 `1920×1080` 为唯一设计画布，通过根节点 `UIScale` 按 `min(ViewportSize.X / 1920, ViewportSize.Y / 1080)` 等比缩放并居中显示。

排查当前代码与 Studio `ReplicatedStorage.UI` 模板，**尚未固定在 `1920×1080` `CenterFrame` 画布上**的移动端 UI 与配置共 5 处：

| 节点 / 配置 | 当前位置与行为 | 问题 |
|---|---|---|
| `TouchAttackFrame`（攻击键） | 独立模板，运行时克隆到 `GameScreenGui` 根下，由 `GameScreenGuiManager:LayoutTouch()` 追踪原生 `JumpButton` 动态计算屏幕像素坐标与尺寸 | 不在 1920×1080 画布内，不同机型屏幕坐标漂移 |
| `TouchSprintFrame`（冲刺键） | 同上，运行时排在攻击键正上方 | 同上 |
| `ThrowStick`（扛人丢置摇杆） | 同上，运行时与攻击键同位置互斥 | 同上 |
| `TouchPaintFrame`（画符退出/重置） | 挂在 `GameScreenGui` 根下，`Anchor=(0.5,1)`、`Pos=(0.5,0,1,-24)`、`Size=300×50` 真实像素 | 脱离 1920×1080 画布；与 `CenterFrame` 内桌面端按钮重复维护，且使用 `TouchEnabled` 而非 `PreferredInput` |
| `GameScreenGui.ScreenInsets` | 当前 Studio 中为 `Enum.ScreenInsets.DeviceSafeInsets`（同时 `IgnoreGuiInset = true`） | 刘海屏下容器区域缩小，与 `UIScale` 使用的完整 `ViewportSize` 基准不一致，且 `ModalButton` 遮罩边缘可能无法铺满真实视口 |

---

## 2. 已确认的核心设计决策

1. **跳跃键自研固定**：屏蔽并隐藏 Roblox 原生 `TouchGui` 中的 `JumpButton`，在 `CenterFrame` 内新增自研固定跳跃按钮（`TouchJumpFrame`），右侧所有操作键在 `1920×1080` 画布上完全自主排版。
2. **保留原生左移动摇杆**：继续使用 Roblox 原生 `TouchGui` 左侧动态摇杆，仅屏蔽其中的 `JumpButton`，兼顾移动手感与低维护成本；进入画符模式时仍按既有逻辑整体关闭 `TouchGui.Enabled`。
3. **画符按钮双端合一**：删除独立的 `TouchPaintFrame`，桌面与移动端统一共用 `CenterFrame` 内的 `ExitPaintButton` 和 `ResetViewButton`（可适度增高按钮设计高度至 `84 px` 提升触控舒适度）。
4. **经典拇指扇形排版**：右侧 4 个操作控件固定在 `CenterFrame` 右下区域——跳跃键在右下角（`190×190`）、攻击键与丢置摇杆在其左上方互斥同位（`190×190`）、冲刺键在跳跃键正上方（`156×156`）；代码完全不写死坐标与尺寸，后续可在 Studio Edit 中直接拖拽微调。
5. **所见即所得模板结构**：在 `GameScreenGui.CenterFrame` 下直接预置 `TouchControlsFrame`（`1920×1080` 透明容器），统一收纳 `TouchJumpFrame`、`TouchAttackFrame`、`TouchSprintFrame`、`ThrowStick`，不再于运行时从 `ReplicatedStorage.UI` 零散克隆 3 个顶层模板。
6. **跳跃按钮全新统一美术贴图**：另行制作并上传 `Assets/UI/JumpButton.png`（`512×512` 透明圆形图标，风格与 `AttackButton.png`、`SprintButton.png` 保持一致）接入 `TouchJumpFrame.JumpButton`。

### 3.2 1920×1080 坐标防碰撞与多端真实尺寸校验

1. **右侧区域防重叠检查**（游戏为横屏 `ScreenOrientation.LandscapeLeft`）：
   - `StaminaFrame` 底边在 `y = 429`；`TouchSprintFrame` 顶边在 `695 - 78 = 617`，纵向间距 `188 px`，完全无重叠。
   - `TouchSprintFrame` 底边在 `695 + 78 = 773`；`TouchJumpFrame` 顶边在 `915 - 95 = 820`，纵向间距 `47 px`。
   - `TouchAttackFrame` / `ThrowStick` 右边在 `1545 + 95 = 1640`；`TouchJumpFrame` 左边在 `1765 - 95 = 1670`，横向净距 `30 px`（斜向圆心距 `≈ 231 px`，远大于两圆半径之和 `190 px`，留出 `41 px` 弧线安全间隙）。
   - `TouchAttackFrame` / `ThrowStick` 左边在 `1545 - 95 = 1450`；底部工具栏 `BottomButtonsFrame` 居中排布（常规 1~5 槽位时右边在 `≤ 1320`），左右留白充足；且 `ThrowStick` 在 `y = 750..940` 偏上，即使满 9 槽也避开重叠风险。
   - `TouchJumpFrame` 右边 `1860`（距右边缘 `60 px`），底边 `1010`（距底边缘 `70 px`），不贴死画布边角。

2. **典型设备真实屏幕像素换算**（按 `scale = min(W/1920, H/1080)`）：

| 设备模拟尺寸（横屏） | `scale` | 跳跃 / 攻击 / 丢置 (`190 px`) | 冲刺 (`156 px`) | 画符按钮高度 (`84 px`) |
|---|---|---|---|---|
| 小屏手机 `667×375` | `0.347` | `66 × 66 px` | `54 × 54 px` | `29 px`（宽 `121 px`） |
| 主流手机 `844×390` | `0.361` | `69 × 69 px` | `56 × 56 px` | `30 px`（宽 `126 px`） |
| 大屏手机 `932×430` | `0.398` | `76 × 76 px` | `62 × 62 px` | `33 px`（宽 `139 px`） |
| 平板 `1024×768` | `0.533` | `101 × 101 px` | `83 × 83 px` | `45 px`（宽 `187 px`） |

主交互按钮在所有主流手机上均达到 `≥ 66 px` 舒适触控直径，同时在 `1920×1080` 画布上的相对坐标完全恒定。

3. **画布单行文本与描边合规**：
   - `TouchJumpFrame` / `TouchAttackFrame` / `TouchSprintFrame` 内的 `ActionText`：设置 `TextScaled = false`、`TextWrapped = false`、`DesignTextSize = 26`（`190 px` 大钮对应 `26~28`，`156 px` 冲刺钮对应 `24`，统一在 `GameScreenGuiManager:Init` 中接入 `ProcessingText` / `TextFitting` 二分拟合，避免 190×190 尺寸下沿用旧 `20 px` 显得过小）；
   - 所有 `UIStroke` 均保持 `StrokeSizingMode = Enum.StrokeSizingMode.ScaledSize`；
   - 所有交互按钮均满足 `AnchorPoint = (0.5, 0.5)`、挂子节点 `UIScale`、配置 `HasInteractionEffect = true`、`HasClickSound = false`、`ScaleWhilePressed = true`、`PressedScale = 0.86`、`PressTweenSeconds = 0.1`。

## 4. 核心技术实现方案

### 4.1 屏蔽原生 `JumpButton` 并保留左侧移动摇杆

Roblox 的 `PlayerModule.ControlModule.TouchJump` 会在触屏设备创建 `PlayerGui.TouchGui.TouchControlFrame.JumpButton`，并且在角色重生、`Humanoid.JumpPower` / `JumpHeight` 变更或重置控制模块时重新将 `JumpButton.Visible` 置为 `true`。

**实现要点**（禁止将 `Humanoid.JumpPower` 设为 `0`，否则自研按钮也无法起跳）：
1. 在 `GameScreenGuiManager`（或独立轻量模块 `TouchJumpController.luau`）中监听 `PlayerGui` 的已有节点与 `DescendantAdded`：
   - 仅定位位于 `TouchGui` 下名为 `JumpButton` 的 `GuiObject`；
   - **不隐藏、不修改** `TouchGui` 或 `DynamicThumbstickFrame` / `ThumbstickFrame`（保留原生左侧移动摇杆）；
   - 对原生 `JumpButton` 执行压制函数 `SuppressNativeJump(button)`：
     - `button.Visible = false`
     - `button.Active = false`
     - `button.Selectable = false`
     - `button.Position = UDim2.fromOffset(-9999, -9999)`（双保险防引擎短帧闪现误触）
   - 监听 `button:GetPropertyChangedSignal("Visible")` 与 `button.AncestryChanged`，一旦引擎将其恢复可见，立即再次置 `false`。
2. 管理器 `Destroy()` 时断开所有压制监听（并记录清理，确保重复初始化幂等）。

### 4.2 自研跳跃按钮输入控制（`TouchJumpController.luau`）

为保持职责单一、与 `SprintController.luau` / `ManualThrowController.luau` 对齐，新增 `Scripts/ReplicatedStorage/Scripts/Client/TouchJumpController.luau`：

1. **按下与长按连跳**：
   - 监听 `JumpButton.InputBegan`（接受 `Touch` 与 `MouseButton1` 测试模拟）：记录当前激活的 `jumpInput: InputObject`，设置 `jumping = true`，立即对当前存活角色 `Humanoid.Jump = true`。
   - 监听 `RunService.RenderStepped`（或 `Heartbeat`，仅在 `jumping == true` 时活跃，避免无谓常驻开销，或通过 `Humanoid.StateChanged` 在落地时补跳）：在按住期间持续维持 `humanoid.Jump = true`，与 Roblox 原生 `TouchJump` 长按自动连跳手感一致。
   - **抬起 / 中断清理**：在以下任意条件触发时立即清空 `jumpInput` 并停止跳跃请求：
     - `UserInputService.InputEnded` 匹配 `jumpInput`；
     - `jumpInput:GetPropertyChangedSignal("UserInputState")` 变为 `Cancel` / `End`；
     - `JumpButton` 或父级 `TouchControlsFrame` 变为不可见；
     - 进入画符模式（`Painting == true`）、打开模态窗口（`ModalButton.Visible`）、打开系统菜单（`GuiService.MenuOpened`）、窗口失焦（`UserInputService.WindowFocusReleased`）或角色移除/死亡。
2. **输入穿透与多点触控**：
   - `JumpButton.InputSink = Enum.InputSink.Activate`（与 `AttackButton` 一致），防止点击跳跃时穿透触发世界镜头旋转或意外攻击；
   - 仅追踪触发按钮的那一根 `InputObject`，与左手移动摇杆、右手滑屏转镜头完全互不干扰。

### 4.3 `GameScreenGuiManager.luau` 精简重构

修改 [GameScreenGuiManager.luau](file:///c:/Users/herong/Desktop/work/DemonShop/Scripts/ReplicatedStorage/Scripts/Client/UIManager/GameScreenGuiManager.luau)：

1. **移除全部动态定位代码**：
   - 删除 `LayoutTouch()` 内的 `JumpSizeRatio` / `MinimumTouchSize` / `JumpGap` 计算与 `Place()` 坐标写入；
   - 删除 `cameraScope`（不再因 `ViewportSize` 重算触控按钮坐标，缩放完全交给 `CenterFrame.UIScale`）；
   - 删除对 `TouchAttackFrame` / `TouchSprintFrame` / `ThrowStick` 的运行时 `Clone()` 与 `Destroy()`（它们现在是 `CenterFrame.TouchControlsFrame` 的静态预制子节点，随 `GameScreenGui` 一起克隆与销毁）。

     - `jumpControlButton = touchJump:WaitForChild("JumpButton") :: ImageButton`
     - `touchAttack = touchControls:WaitForChild("TouchAttackFrame") :: Frame`
     - `attackButton = touchAttack:WaitForChild("AttackButton") :: ImageButton`
     - `touchSprint = touchControls:WaitForChild("TouchSprintFrame") :: Frame`
     - `sprintButton = touchSprint:WaitForChild("SprintButton") :: ImageButton`
     - `throwStick = touchControls:WaitForChild("ThrowStick") :: Frame`
   - 新增 `GetJumpButton(): ImageButton` 接口，供 `ClientProcessingManager` 装配 `TouchJumpController`。
3. **统一显隐状态机 `RefreshTouchVisibility()`**：
   - 统一以 `local isTouch = UserInputService.PreferredInput == Enum.PreferredInput.Touch` 为唯一移动端判定口径（移除 `TouchEnabled` 混用）；
   - 不再依赖原生 `jumpVisible` 门控；
   - 显隐规则：
     - `touchControls.Visible = isTouch and not self.painting and not self.windowOpen`
     - `touchJump.Visible = true`（跟随 `touchControls` 整体显隐）
     - `touchAttack.Visible = not self.carryingBody`
     - `throwStick.Visible = self.carryingBody`
     - `touchSprint.Visible = true`（`SprintController` 仅控制 `SprintButton` 的激活色/不可冲刺态显隐，与父容器一致）
   - 画符按钮统一：
     - `self.buttons.ExitPaintButton.Visible = state.painting`
     - `self.buttons.ResetViewButton.Visible = state.painting`
     - 删除 `touchFrames.TouchPaintFrame` 相关字段与逻辑。
4. **注意 `UIManager.luau` 中的 `BindCamera` 与 `TextFitting`**：
   - `TouchControlsFrame` 在 `CenterFrame` 内，进入 `Init` 时其子级所有 `TextLabel` 会自动被 `self.texts:Watch(node)` 与 `TextFitting.FitMarkedRoot(gameScreenGuiNew)` 纳管，无需特殊处理。
