# DemonShop UI 重构任务拆解

模型与推理等级按交付复杂度推荐。设计评审与设备验收作为独立任务。视觉风格由 Phase 1 的设计评审决定。

| ID | 阶段与交付 | 复杂度 | 依赖 | 推荐模型 | 推理 | 验收标准 |
|---|---|---|---|---|---|---|
| T01 | 锁定现状基线及采集流程 | 中 | Phase 0 清单 | GPT‑6.2 Sol | high | UI 快照可按规范路径复查，脚本与模板时点一致。补 OBS、实体端和缺失状态。记录测试数据隔离 |
| T02 | 约束构建器与隔离恢复 | 高 | T01、R01/R09/R10 | GPT‑6.2 Astra | high | 逐构建器列出写入范围。正式恢复两次结果一致。基线、主题实例和基础网络/消息完整。回退从新导出可恢复 |
| T03 | 信息架构和视觉探索评审 | 高 | T01 | GPT‑6.2 Astra | high | 空手、持有、画符、转化和提交的层级与视觉路线经评审。保留各状态文案和无障碍反馈需求 |
| T04 | Design System 及组件模板 | 高 | T02、T03 | GPT‑6.2 Astra | high | 发布颜色、字体、层级、圆角、边框、间距、图标及交互状态规格。固定 1920×1080、DesignTextSize 与 ScaledSize 按节点核查 |
| T05 | 项目设备采样和 HUD / 触控几何 | 高 | T01、T03 | GPT‑6.2 Astra | high | 桌面、超宽、手机横/竖、平板采样。项目禁放参考覆盖经确认的系统区。触控目标触达、摇杆手势、边界和文本可读通过 |
| T06 | 基础 UI 生命周期及节点寻址迁移 | 高 | T02、T04 | GPT‑6.2 Astra | xhigh | 启动、补发、重生、销毁与重建无重复、无漏监听。硬依赖节点有定位错误。窗口层级、遮罩、动效和开放接口通过基础契约 |
| T07 | 游戏 HUD、提示、通知和文本迁移 | 高 | T04、T05、T06 | GPT‑6.2 Astra | high | 金币、池/架、持有、任务、倒计时和通知的输入/格式/优先级正确，设定的中英长短样本通过字号与可读验收 |
| T08 | 工具栏和设备按钮迁移 | 高 | T04、T05、T06 | GPT‑6.2 Astra | high | 键鼠及触控装备切换、顺序、装备高亮、预览镜头可用。最大合法槽数无遮挡，重生、移除和重复快切无残留 |
| T09 | 原生 Prompt 与世界标牌迁移 | 高 | T04、T05、T06 | GPT‑6.2 Astra | high | 从当前有效、失效和遮挡场景验证 E、手柄 X 和触摸 hold。原生交互与 HUD 引导一致。12 块牌的目的地、光照和阅读距离经回查 |
| T10 | 画符 HUD、指针和笔迹表现迁移 | 很高 | T04、T05、T06、T08 | GPT‑6.2 Astra | xhigh | 横竖屏和桌面完成进出、落笔/旋转、重置、覆盖率、退出后的触控恢复。平面/曲面与观察者画面正确，对象和纹理预算回归通过 |
| T11 | 资源、文本与恢复包对照 | 中 | T02、T07–T10 | GPT‑6.2 Sol | high | 源节点、资源 ID、加载权限、预览模型、语言表和新导出一一对应。隔离重导无旧主题写入和丢失引用 |
| T12 | 状态机、双客户端及发布前回归 | 很高 | T01、T06–T11 | GPT‑6.2 Astra | xhigh | 主链路桌面与手机横/竖，空态、异常提示、晚加入、满池满架、相机和展示生命周期按矩阵验收。同一数据边界和协议契约通过，证据可由新会话复现 |

先完成 T01，再并行推进 T02、T03。T04、T05 确立后可安排组件生产与基础契约迁移。各玩法 UI 的合并顺序依赖 T06，最终由 T11 和 T12 验证跨模块交付。每次迁移以相关模板路径及原入口作为验收位置，确定设计已覆盖业务状态后再更新恢复导出。
